### 🤖 Gemini

把这三个仓库放在一起看，脉络非常清晰：pi-goal-x 解决了**单智能体长程运行的工程韧性**（缓存前缀、预算、退避、持久化锁），herdchestra-lite 解决了**验收防伪与宿主无侵入适配**（四阶段契约哈希冻结、0–100 可复现 Rubric、双视角支付意愿审计、Schema 级工具门），而 AGENTS.md 解决了**多智能体规模化协作的并发物理定律**（宏观换任屏障 + 微观 STM 看板、stamp + 写入口 $W$
、take-or-die 唯一持令者、多 worktree 机械集成、UFSS 零转义字面量）。

做两个版本最大的忌讳，是把一边的表面机制硬塞进另一边的物理底座，破坏各自的架构不变量。两者应当是**同一套协作灵魂在两种宿主约束下的同构投影**：

- **标准版（Autonomous / Claw-like）**：拥有完整的 Clojure/JVM 单机单例、Datalevin 当前态库与自定义工具求值器，优势在于**强事务边界与上下文物理切割**，需要从 Lite 和 pi-goal-x 引入**防主观放水的验收标尺**与**真实 Provider 边界的生存韧性**。
- **Lite 版（Parasitic / omp 插件）**：寄生在 omp 宿主与 JS 运行时之上，零额外部署成本，遵守“投影不改写、适配不改造宿主”，需要把 AGENTS.md 的并发控制与视野隔离**降维成插件可拦截的原语**（文件锁、消息投影、worktree 脚本编排）。

以下按**「标准版引入什么」「Lite 版引入什么」「四处核心冲突如何裁决」「如何共享资产降低双线维护成本」**展开。

### 一、 标准版（AGENTS.md 架构）应从 Lite 与 pi-goal-x 引入的改进

AGENTS.md 的并发状态机非常严密，但在**“怎样算真正做好了（防 Goodhart）”**和**“面对真实模型 API 故障/烧钱/死结时怎么活下来”**这两件事上，herdchestra-lite 与 pi-goal-x 已经踩过了真坑，可以直接反哺标准版。

#### 1. 用 Lite 的「契约哈希冻结 + 双视角 WTP 实操审计」硬化 Plan 与 Reviewer（补强 §2.3、§2.4）

AGENTS.md 目前让继任 Reviewer 读 plans/<name>.md 并用 clj-review 看代码，提交空账 (review {:findings []}) 即可晋级结案。这有一个隐患：clj-review 是纯静态只读的（无 .call），继任 Reviewer 很容易看着代码结构工整就放行，漏掉真实运行时的交互断裂。

- **底稿结构化验收标尺**：保留 plans/<name>.md 为唯一底稿（不拆成三个输入文件），但要求 S1 必须在底稿中产出覆盖正常、错误、并发、恢复路径的 CASE-* 列表及 **0–100 可复现评分细则（Rubric，要求两独立审计员分差 **$\le \pm 5$**
   ）**。
- **交接时 SHA-256 契约冻结**：借鉴 Lite 的 freezeManualAcceptanceObjective。当 Plan 在 待执行 提交空账启动执行层时，内核自动计算 plans/<name>.md 的 sha256 写入 Mission 记录。执行期间若人类直接修改了底稿（§2.3 允许），stamp/哈希变化会显式触发一次增量对齐，绝不允许拿着被静默改弱的标准结案。
- **独立实操审计与双视角否决权**：在 收尾（:closing）阶段，除了静态 Reviewer 检查外，引入 Lite 的 **S4 实操验收准则**——必须通过只读受控环境（如 tmux 真实按键抓屏、Web 无头/受管浏览器实操、/tmp 隔离副本故障注入）收集行为证据，严禁拿单元测试通过率或构建成功充当验收证据。每个 CASE 按 user_score（外部用户愿付价值）与 developer_score（内部工程质量）双打分，取 min(user_score, developer_score) 对比阈值，并将完整报告落盘到产物区（artifacts/）。

#### 2. 用 pi-goal-x 的「双块锚点重放 + 显式缓存断点前移」补完 Pair Hint（补强 §5.4、§6.2）

AGENTS.md §6.2 规定了同一 Epoch 的消息序列前缀法则，但没有处理各家 Provider 缓存协议的物理细节。pi-goal-x 的 goal-live-retention.ts 和 goal-prompt-cache.ts 提供了现成答案：

- **稳定块与易变块分离**：将 Pair Hint 注入拆为**低频块**（口诀、语言纪律、Scope 目标、看板 clean-break 全量快照）与**高频块**（墙钟时间、已用回合、看板小 delta）。高频块不在原位覆写，而是按历史锚点在尾部增量保留（设上限如 32 条 / 4 KiB），保证第 $N+1$
   次请求严格以第 $N$
   次请求为前缀；超限或低频块变化时再做一次 clean-break。
- **显式缓存标记前移**：在 ModelPort 序列化层，针对 Anthropic（cache_control）与 Bedrock（cachePoint），不要让缓存断点落在每轮必变的瞬态计数尾块上，而是自动前移锚定在最后一个真实历史块或 clean-break 快照块上，白捡高命中率且不改业务状态。

#### 3. 用 pi-goal-x 的「无人值守防雪崩三件套」加固守卫与模型端口（补强 §2.5、§5.2、§5.4）

AGENTS.md §2.5 规定“Nudge 胜出，不判断 agent 是否原地打转”。在长程无人值守下，这需要三道物理护栏配合：

- **空转退避（Idle Continuation Backoff）**：吸收 pi-goal-x 的 paceIdle。不改变“禁止自然停止”的铁律，但守卫区分“本轮是否有实质状态推进（看板变更、有效文件提交、非空调查）”。首轮无实质推进立即 0ms Nudge；若连续无推进，按 30s → 60s → 120s → 240s → 300s 转入 :retry-wait 定时唤醒。一旦出现看板变更或人类新输入，立即归零。这能防止模型在逻辑死胡同里一秒钟刷十次空回合烧穿账单。
- **上游断流 vs 配额耗尽的精确分流**：吸收 goal-format.ts 的错误分类。没有操作员取消信号却收到流中断/aborted，一律归入上游网络断流走有界退避，绝不误判为取消；而 insufficient_quota / 计费拒绝属于确定性不可重试错误，直接走 P4 守卫打上 :stalled 并暴露可观察事件，绝不空跑重试预算。
- **微观死结的只读会诊（Blocker Oracle）**：蜂群个体全用 @task 模型（铁律 #8），遇到复杂架构死结可能反复 release / reopen。可借鉴 goal-oracle.ts：当同一任务或同一归一化阻塞指纹（fingerprint）连续失败达阈值时，内核自动用主模型跑一次**只读无副作用会诊**，把替代路径以 comment 追加到看板，并要求下一个认领者至少做一次实质尝试。这与“宏观主模型把关、微观 @task 施工”的铁律完全契合。

#### 4. 用 Lite 的「阶段方法论纪律 + Schema 级认知锚点」降低长程漂移（补强 §4.1、§6.1）

- **方法论进提示词而非只留文档**：Lite 的 METHOD_DISCIPLINE（S1 Howard/Dalio/Bezos，S2 Polya/Schoenfeld，S3 Knuth，全阶段 Goodhart 守卫，且规定“只有改变决策或检查时才点名方法”）非常精炼，应直接合入标准版的 COMMON、PLAN_PROMPT 与 REVIEWER_PROMPT。
- **合并 Tool Gate 与 :intent / :scope**：标准版每次工具调用已有 :intent（核定 bytes * 50ms 期限）和 :scope。吸取 Lite tool-gate 的经验，在工具 Schema 层直接约束 :intent 必须以当前会话绑定语言写出本步动作与三闸门简短核验（系统拿它的字节数算期限，执行前无需额外剥离冗余字段），一举两得。

### 二、 Lite 版（omp 插件架构）应从 AGENTS.md 引入的改进

Lite 版不能改 omp 宿主源码，也没有 Clojure STM，但 omp 暴露了极强的钩子（before_agent_start、context、before_provider_request、tool_call、tool_execution_end、runSubprocess），且**子代理同样会加载插件扩展列表**。利用这一点，AGENTS.md 最核心的四项机制可以在纯 .mjs 插件中优雅落地。

#### 1. 新增第四个独立入口 src/workspace-gate/index.mjs：给宿主文件工具套上 stamp + 写锁 $W$


目前 Lite 版在 src/pi-goal/facade.mjs 中写着 if (ctx.agent.kind !== "main") return;，让子代理跳过了 goal 管理；这导致主会话派出的多个子代理在共享工作区裸奔写文件、并发跑 bash 测试，极易互相覆盖。

- **跨主从会话的轻量受保护提交**：新增第四个清单入口 workspace-gate（对 main 与所有 subagent 均生效）：**无锁读取采信**：在 tool_execution_end 监听 read 工具，调用 fs.statSync(path, { bigint: true }) 采集精确的 { mtimeNs, size }，存入当前会话内存的 readSet: Map<absPath, Stamp>。**写入口 **$W$**
   与 stamp 复核**：复用 pi-goal-x 成熟的原子目录/文件锁机制（.pi/locks/workspace-w.lock，含 PID 存活检测与超时清理），在 tool_call 拦截 write / edit 时先拿锁 $W$
   ，复核该会话 readSet 中目标文件（及声明依赖文件）当前的 { mtimeNs, size }；一旦不一致，立即返回 { block: true, reason: ":FILE_CONFLICT — 文件已被其他工人修改，请重新 read 后再提交" }，在触碰磁盘前拦截覆盖事故！
- **唯一 Shell 持令门（Holder Gate）**：在同一个 workspace-gate 中拦截 bash 工具——同一 worktree 下运行 bash 必须先持有 $W$（或检查当前子代理是否持有 .pi/locks/shell-holder.json 令牌），防止一个工人正在跑测试/构建，另一个工人把源码改了一半。

#### 2. 激活多 Worktree Slice 并行编排（兑现 .gitignore 里的 .herd-worktrees/）

注意 herdchestra-lite 的 .gitignore 里其实已经预留了 .herd-worktrees/！AGENTS.md §2.2 与 §5.3 的多 worktree fork/join 模型正是解决 Lite 版“开 20 个工人互相踩脚”的终极解药：

- **S3 切片与 Worktree 一一对应**：S3 coordination.md 定义互不相交的 Slice（每个 Slice 指定目标、depends_on 与 done_when）。
- **注册轻量编排工具（fork_slices / join_slice）**：在主会话提供工具，为每个就绪 Slice 在 .herd-worktrees/<slice-id> 创建独立 Git worktree；派发给子代理时将其工作目录指向对应 worktree。子代理完成后进入 FIFO 队列，join_slice 在主分支集成锁下执行 git rebase master + git merge --ff-only，把单目录并发冲突彻底化整为零。

#### 3. 引入「中心化换任接力屏障（Relay Barrier）」与「首评前写锁」

Lite 版目前在执行阶段由同一个长会话一竿子插到底，即便审计员打回，也是原会话带着旧偏见修补。

- **阶段切换强制 Clean-Break**：当 S3 批准进入执行期，或者当 S4 可见审计员返回 disapproved 打回返工时，联动 pi-context 自动在当前节点打书签并切出一条**干净的新分支**（只注入冻结的契约路径、未通过的 CASE 清单与真实磁盘现状，剥离前任冗长的试错对话），模拟 AGENTS.md 的 Context Barrier。
- **审阅期只读硬门禁**：借鉴 AGENTS.md 的 :WRITE_LOCKED_BEFORE_FIRST_REVIEW 与 Plan 边界。在草稿/修订阶段（/goal-x、/goal-tweak），主会话除了通过三个 submit_* 工具写契约文档外，用 tool_call 钩子硬性拦截对任何业务源码的 write/edit，但开放一个只读调查子代理入口（或仅放行只读 read/search），防止规划期偷跑实现。

#### 4. 硬化任务树守卫：「父项保留实质，严禁子项全完自动关父项」

在 src/manual-acceptance/guards.mjs 与 src/pi-goal/tool-wrap.mjs 中加入 AGENTS.md 铁律 #2（A02-06）：

- 拦截 update_goal_task：当某个父任务的所有子任务刚刚变为 complete/skipped 时，禁止在同一批次调用中将父任务本身也标为 complete。
- 要求父任务的完成必须单独提供**合龙与集成验证证据**（证明各子任务产物已在入口处接通），消除模型把父任务当“分组标题”顺手勾掉的恶习。

#### 5. 工具回执与提示词引入 UFSS 围栏格式与紧凑 Scope 预算观

- 在 Lite 自有工具（三个 submit_*、守卫拒绝消息、审计报告反馈）的文本输出中，凡涉及代码片段、路径与多行文本，改用 AGENTS.md §6.3 的 #"""..."""# 围栏呈现，减少 JSON 双重转义带来的模型读写误差。
- 为 pi-context 补充类似 assume 的轻量工具或固定格式标记，让关键结论在 context_compact 分支压缩时被确定性保留，其余探索过程果断裁除。

### 三、 必须提前裁决的四处核心冲突

两套设计在以下四个地方存在正面冲突，建议按各自宿主定位明确划界，不要模糊妥协：

|  |  |  |  |
| :--- | :--- | :--- | :--- |
| 冲突维度 | herdchestra-lite / pi-goal-x 现行规则 | AGENTS.md 现行规则 | 建议裁决方案 |
| **1. 规划期人机交互节奏** | S1、S2、S3 每写完一份文档必须停下等人类明确点头，最后弹确认框（慢规划防错）。 | 常授权无人值守：除 S1 .ask 和初任空账 .ask 外绝不停下等人类，S1→S2→S3 靠换任互审自动晋级，Nudge 胜出。 | **双模分治**：**标准版**严格走常授权无人值守（人类只抓 S1 意图澄清、随时直接改 plans/<name>.md 或按 Esc）；**Lite 版**默认保留交互式 /goal-x（契合 CLI 结对习惯），另增一个 /herd 命令启用无人值守自动晋级模式。 |
| **2. 规格文档物理形态** | docs/manual-acceptance/<slug>/ 下拆成 requirements.md、development-guide.md、coordination.md + report.md 四份文件。 | 唯一持久底稿 plans/<name>.md（首评前只读，支持人类直接编辑）；报告归产物区。 | **结构同构、外皮各异**：**标准版**坚持单文件 plans/<name>.md（内含规范化的 S1 CASE+Rubric / S2 / S3 三节）+ 独立验收报告产物；**Lite 版**保留四文件目录（避免破坏现有 17 个验收 CASE 基线），两者共用同一套 CASE/Rubric 解析规则。 |
| **3. 并发工人组织形态** | 提示词口号驱动：“维持工人数量，通常 20 个以上”“一个 DevOps + 尽可能多工程师”。 | 跨模块拆 N 个互不相交 Worktree Slice；单 Worktree 内固定槽位 + STM 看板 + take-or-die 唯一 Holder。 | **废除同目录盲目堆人**：两边统一收敛为**「跨 Slice 靠多 Worktree 激进并行（N 按因果最大化）+ 单 Worktree 内靠写锁 $W$ 与唯一 Shell Holder 串行保护」**。 |
| **4. 暂停（Pause）语义** | pi-goal-x 有完整的 paused 状态、/goal-pause 与三阶暂停顺序（together / goal-first / turn-first）。 | 铁律 #5/#6：**系统不提供暂停态**；Esc 递归取消当前 run，重开即从持久化现场继续。 | **标准版**不设 paused 协议状态（UI 若需“暂停新领取”仅作守卫门投影，见 AgentZero 基线 §3.1）；**Lite 版**保留 pi-goal-x 原生 pause/resume 不动，重点补齐 Esc 时对在途审计与子代理树的递归 abort。 |

### 四、 跨版本共享资产与演进次序建议

为了让两个版本互相加速而不是造成双倍研发负担，可以把两者的关系定为**「Lite 探路验证策略，Standard 固化自治底座」**：

1. **直接共享的纯规格与测试语料（Write Once, Verify Both）**：**S1–S4 验收语法与评分器逻辑**：CASE-* 标题、PASS threshold、双视角 min(user_score, developer_score) 裁决表（Lite 的 requirements.mjs / scores.mjs 与标准版的验收模块保持完全一致的输入输出语义，测试向量通用）。**UFSS 读写器测试集**：标准版用 Clojure 实现完整 Reader/Printer，Lite 版可用百行 JS 实现输出端 Pretty Printer，共用同一组边界字符串（尾引号、Windows 反斜杠、缩进剥离、\r 回退）做双射测试。**并发交错验收剧本（F01–F10 文件锁与 stamp 冲突）**：同一套状态交错表，既测 Lite 的 workspace-gate 文件锁拦截器，又测标准版的 hc/core/workspace_gate。
2. **推荐推进顺序**：**第一步（先在 Lite 版低成本试水机制）**：在 herdchestra-lite 中加上 workspace-gate（stamp + $W$ 拦截）与 .herd-worktrees/ Slice 工具，以及父任务禁自动完成守卫。几天之内就能在真实日常开发任务中观察大模型对 :FILE_CONFLICT、唯一 Shell 限制和多 worktree rebase 的真实反应与提示词摩擦点。**第二步（反哺标准版 hc/core 与 hc/compose）**：拿着 Lite 实测打磨好的冲突提示文案、Nudge 空转退避参数和双视角验收模板，在标准版按 AGENTS.md §8.4 的五阶段顺序（STM 控制内核 → 受保护文件入口 → take-or-die 生命管理 → Shell 适配 → LangChain4j ModelPort 含缓存断点前移与断流恢复）干净地一次性建好 Clojure 底座。

如果你希望继续深入其中某一块（例如：**Lite 版 workspace-gate 与多 worktree 工具的精确接口设计**，或者**标准版如何把双视角 WTP 验收与 pi-goal-x 缓存/退避机制写进 DEBT.md / 包级 AGENTS.md**），我们可以直接挑一边往下推演。

### 🤖 Gemini

#### 一、 两个前置设计裁决

##### 1. S2 的大师归属：XXX = James Bach（完整组合：James Bach、Glenford J. Myers、Gerald M. Weinberg）

将原 S1 拆分为 **S1 头脑风暴（需求与决策）** 与 **S2 手工测试方法论（验收契约与标尺）** 非常关键——原先把需求收敛和全分支手工用例混在一阶段，容易导致需求还没吵透就急着列测试，或者列测试时漏掉破坏性边界。

## 1 十条硬约束（不变量铁律）

以下十条是全系统的最高不变量。若后文细节与本节存在任何歧义，以本节为准：

1. **零第三方依赖、零宿主篡改、多入口故障隔离。** 运行时严禁引入外部 npm 包（包括但不限于旧版 `pi-goal-x` 与 `pi-context`），严禁修改宿主或依赖库源码，严禁篡改 `AgentSession.prototype` 或 `TUI.prototype`。插件拆分为三个独立清单入口（主装配入口、`tool-gate` 协议门入口、`workspace-gate` 工作区保护入口），任一入口加载失败不得阻断其余入口或弄崩宿主会话。
2. **五阶段严格递进与渐进式 SHA-256 契约冻结。** 任何 Mission 必须依序推进 **S1（头脑风暴）→ S2（手工测试方法论）→ S3（目标导向开发指南）→ S4（开发者协调手册）→ S5（蜂群自治开发）**。前序阶段晋级时，系统立即计算其交付文档的 `sha256` 并冻结至使命契约；后续阶段及 S5 执行者对已冻结的前序文档严格只读。若人类操作员直接编辑了已冻结文档，系统以人类版本为准重新对齐，严禁静默覆盖或拿篡改后的标准结案。（见 §2.2）
3. **宏观中心化换任与微观去中心化蜂群严格咬合。** S5 的每个 Slice 执行任期以中心化评估窗口（Phase A）开启：单一主模型 `Reviewer` 只读核验现场并提交 `review({ findings })`；若台账非空，`Reviewer` 退场，转化为看板根任务并唤醒 `@task` 蜂群（Phase B）并发施工；仅当看板全部根任务 `:done` 且无在途动作时，原子触发接力屏障——退休本任、建立上下文屏障、唤醒无前任对话包袱的新任 `Reviewer`。（见 §2.4）
4. **父项始终保留实质，严禁子项完成自动关闭父项。** 在看板中，拆分优先于原子认领；父任务拆出子项后进入 `waiting`，子项全部 `:done` **仅解除父项等待使其恢复 `ready`**，绝不自动折算为父项 `done`，且严禁在同一批次调用中将刚解除等待的父项顺手标为 `done`。父项必须凭独立的合龙与集成结果显式结项。（见 §3.3）
5. **文件写入一律走受保护提交合同（纳秒级 `stamp` + 写入口 $W$ + 原子落盘）。** `read` 不加锁，自动在当前会话内存登记精确凭据 `stamp = { mtimeNs, size }`（严禁比较 `atime`，严禁降级为毫秒浮点）。任何 `write`/`edit` 在 `tool_call` 阶段必须先取得所在 worktree 的排他写锁 $W$，复核本会话 `read-set` 中目标文件与声明依赖文件的当前 `stamp`；任一不符立即在触碰磁盘前拒绝并返回 `:FILE_CONFLICT`。（见 §4.2）
6. **抢令牌（`take_or_die`）不可逆，持令者独占 `bash` 且无责即死，新生无记忆。** 普通蜂群个体禁止调用 `bash`（拒收 `:TOKEN_REQUIRED`）。个体仅在耗尽有价值受保护工作且存在未结 `:needs-token` 任务时调用 `take_or_die({ request_id, confirm: "i-hereby-confirm-i-die-without-regret" })`：赢者成为唯一 `Holder`，动态承担全看板所有 `:needs-token` 责任（仅在单次 `bash` 运行期或文件落盘期占 $W$，等待期释放 $W$）；输者在同一看板锁事务内公开移交剩余普通责任与认领并逻辑死亡；`Holder` 在完整责任集合 $R(a) = \emptyset$ 时同一事务释放令牌并逻辑死亡。死亡后槽位通过 `runSubprocess` 拉起全新 `agent_id`，绝不继承前世私有对话。（见 §3.4）
7. **常授权无人值守（Nudge 胜出，配空转退避）与 Esc 递归取消。** 默认 `/herd` 模式下，合法停止出口只有三个：S1 阶段调用 `ask({ question })` 挂起等待人类回答；S5 初任 `Reviewer` 首次空账且现场已满足契约时转为一次性 `ask` 询问后续意图；S5 终局实操审计全部达标结案。除此以外绝不弹窗审批、绝不自然停止；未达出口结束回合时自动注入 Nudge（连续无实质进展时按 `30s→300s` 指数退避）。系统不设协议级暂停态；操作员按 `Esc` 或运行 `/herd-cancel` 时，取消信号沿主会话与整棵 `runSubprocess` 子会话树递归传播，如实标记 `:cancelled` 或 `:outcome-unknown`。（见 §2.5、§6.2）
8. **规划期源码写锁与唯一调查原语 `devops`。** S1–S4 规划代理除通过阶段工具写入当前阶段对应的 `plans/<slug>/s1..s4-*.md` 外，对整个仓库严格只读（硬拦截 `write`/`edit`/`bash`）；调查仓库事实只能调用同步工具 `devops({ verbose_intent })`，复用同一任期专属只读调查子代理并原样返回其最终报告。（见 §2.2、§4.1）
9. **模型归属、独立实操审计与 Agent Hub 全程可见。** 主会话（`Coordinator` / `Plan`）、中心化 `Reviewer`、S5 独立实操 `Auditor` 与只读 `Blocker Oracle` 使用主模型（Main Model）；`devops` 调查员、蜂群普通 `Worker` 与 `Holder` 一律使用用户配置的 `@task` 模型。一切子代理均通过 `runSubprocess` 持久化会话产物并以实名在 `omp` Agent Hub 中可见。任何自动化测试、CI、类型检查或构建结果均不构成 S5 最终验收证据。（见 §2.1、§2.4）
10. **投影不改写：出站 `Scope` 预算裁剪与 UFSS 低噪呈现。** 每个非豁免工具调用通过 Wire Schema 强制携带 `:scope` 注解与中文思考锚点，`tool_call` 核验记账后剥离参数；历史修剪仅在 `context` 钩子的出站请求副本上执行，绝不涂改宿主持久化的 `.jsonl` 会话树。插件向大模型返回的一切结构化文本回执一律采用 **EDN/UFSS 变长围栏格式（`#"..."#` 与 `#"""..."""#`）**，消除 JSON 转义噪音。（见 §5.2、§5.4）

### 2.3 多 Worktree Slice `fork` / `join` 编排

在 S5 阶段，主会话按冻结的 `s4-coordination.md` 调度 Slice 级并行，消除单目录二十人踩踏：

1. **`fork_slices({ slices })`**：对所有 `depends_on` 已满足的 Slice，在 `.herd-worktrees/<slug>/<slice_id>` 创建基于当前目标主分支（以下简称 `base`）的独立 Git worktree，初始化该 worktree 专属的看板 `.herd/missions/<slug>/slices/<slice_id>/board.json`、写锁 `$W$` 与令牌槽，启动该 Slice 的任期循环（Phase A `Reviewer` ⇄ Phase B `Swarm`）。N 不设人为上限；磁盘或句柄不足时返回 `:INSUFFICIENT_WORKTREES` 供降数重试。
2. **FIFO 队列式 `join_slice({})`（非竞速）**：
   * 不同 Slice 负责互不重叠的工程目标，绝不把同一份活派给多个 Slice 搞赢家通吃，不存在 `:sibling-accepted` 兄弟取消。
   * 当某个 Slice 通过其内部继任 `Reviewer` 空账验收且达到单任期静默条件（Quiescence）后，进入已完成 FIFO 队列。
   * `join_slice` 每次取出队首结果，获取**主分支集成锁**，在该 Slice 的 worktree 内检查是否已线性对齐最新 `base`（若 `base` 已前进，唤醒该 Slice 的 `Holder` 执行 `git rebase <base>` 并复核冲突；若冲突因方向性淘汰不可解，`Holder` 调用 `abandon_slice({ reason })` 丢弃该 worktree 并上报，不阻塞其余 Slice）。
   * 对齐通过后，主工作区执行机械 `git merge --ff-only`，释放集成锁，向主会话内联返回该 Slice 的完整结项报告全文（不截断、不摘要）。Worktree 在 `join` 或 `abandon` 后保留 7 天备查（可配置），随后自动 GC。

### 2.4 任期双相循环（`Reviewer` ⇄ `Swarm`）与终局实操审计（`Manual Auditor`）

#### Slice 内部任期循环
1. **Phase A（中心化评估窗口）**：每任期开启时启动干净的 `Reviewer` 子会话（主模型），仅开放只读工具与 `review({ findings })`。
   * **初任首评**：对照 `s1..s4` 契约与当前 worktree 现场提交非空 `findings: [{ key, value }]`。若初任在主工作区首次即提交空账且现场确实已满足全部契约，系统转为一次性 `ask({ question: "契约已满足，接下来做什么？" })` 交还人类。
   * **继任者首评决断**：继任 `Reviewer` 在完全看不到前任对话与蜂群草稿的干净视野中独立核验。若提交**空账 `[]`**，且通过单任期 Quiescence 检查（无在途 `:applying`/`:running`/`:uncertain` 动作、无未结 `:needs-token` 任务、不持有 `$W$`、相对 `base` 可 `--ff-only`），本 Slice 即告完成入队；若提交**非空 `findings`**，立即打回进入新一轮 Phase B。
2. **Phase B（微观蜂群施工期）**：`Reviewer` 提交非空台账后退场，系统在同一看板锁事务内将每条 `{ key, value }` 实例化为看板根任务 $T_k$（`state = "ready"`），按槽位容量并发拉起 `@task` 蜂群个体施工。每当根任务 $T_k$ 被显式 `finish_task`，对应台账键 `key` 置 `null`。
3. **原子接力屏障（Relay Barrier）**：当全部根任务 `:done`、未结任务集合 $U = \emptyset$、无在途动作且 `Holder` 已无责退休时，系统在同一原子状态提交中将当前任期标为 `:retired`（迟到请求一律拒收 `:TENURE_RETIRED`），写入上下文屏障，开启下一任 `:successor` `Reviewer`。

#### 全局收尾与 S5 独立可见实操审计
当全部 Slice 完成 `join` 合入主工作区后，主会话触发终局验收，系统自动调用可见审计员（`Manual Auditor`）：
1. **前置与事后双重复核**：启动前及审计子进程退出后，两次校验 `s1..s4` 四份文档均存在、非空且 `sha256` 与冻结契约分毫不差；任一篡改或缺失立即判定 `disapproved`。
2. **审计员隔离边界**：克隆宿主 `task` 代理为 `"Manual acceptance auditor"`，工具集锁死为 `["read", "search", "find", "bash"]` 并清空 `spawns`（严禁再派子代理），单目标并发互斥（新审计自动 `abort` 旧运行），硬超时 60 分钟，会话产物在 Agent Hub 全程可见。
3. **实操铁律**：
   * 审计员必须按 `s2-manual-tests.md` 文档顺序亲自执行每一个 `CASE-*`；
   * 涉及 TUI 面板、对话框、斜杠命令与主题渲染的路径，必须在 `tmux` 中启动真实 `omp` 发送按键并抓取屏幕保存至 `plans/<slug>/evidence/`，在报告中引用证据路径与可见行，严禁未抓屏声称通过；
   * 涉及缺失依赖、损坏配置、非法入口的错误分支，必须将仓库复制到 `/tmp` 隔离目录制造破坏并运行验证，严禁污染当前产品工作树；
   * 通过 `yield` 提交符合严格 Schema 的 `{ report_markdown, scores: [{ case_id, user_score, developer_score }] }`。
4. **防绕过结案闸门**：内核独立解析 `s2-manual-tests.md` 的 CASE 列表，逐项计算 `final = min(user_score, developer_score)`，核查缺失、未知、重复或越界分数。全部达标后，内核原子写出 `plans/<slug>/s5-report.md` 并签发绑定 `(missionId, revision)` 的一次性结案批准凭证；任何绕过本次批准凭证直接将使命改为 `:completed` 的调用一律抛出硬拒绝。若任一 CASE 未达标，内核输出完整问题清单并将未通过 CASE 转为新一轮返工根任务，使命保持活跃继续推进。

### 2.5 双轨模式（`/herd` vs `/herd-pair`）与防停机 Nudge

1. **`/herd <seed>`（默认：常授权无人值守模式）**：
   * 仅在 `S1` 存在影响全局的重大歧义时，允许调用 `ask({ question })` 挂起等待人类回答；
   * `S1 → S2 → S3 → S4` 每一阶段的晋级由干净视野的继任 `Plan Reviewer` 严格对照阶段标准互审放行，写完 `s4` 自动冻结契约进入 `S5` 蜂群开发与实操审计，直至 `s5-report.md` 全绿结案。
2. **`/herd-pair <seed>`（结对门禁模式）**：
   * 在 S1、S2、S3、S4 每一份阶段交付文档写盘并通过自审后，显式停下请人类操作员审阅确认（人类可直接修改 `plans/<slug>/s*.md` 文件或口头提意见），人类明确同意后才解锁下一阶段；进入 S5 后同样无人值守自治直至 S5 审计完成。
3. **Nudge 防自然停止与空转指数退避**：
   * 在任何非合法出口处（非 S1 `ask` 等待、非 `/herd-pair` 阶段门禁等待、非 S5 终局 `:completed`、非 `:stalled` 确定性故障），一旦代理结束回合，守卫立即拦截并注入 Nudge 消息驱动下一轮。
   * **空转退避保护**：若本轮产生了实质进展（阶段文档变更、看板状态迁移、受保护文件落盘、非空调查报告），下一轮立即 `0ms` 触发；若连续回合无实质进展，首轮仍立即触发，随后按 `30s → 60s → 120s → 240s → 300s` 退避等待（不消耗活跃计时，人类发消息或看板变化立即清零退避）。

## 3 微观蜂群执行层：文件锁看板、拆分优先与 `take_or_die`

每个活动 worktree 维护一份独立控制目录 `.herd/missions/<slug>/slices/<slice_id>/`，由同目录原子锁文件 `.herd/locks/<slice_id>.board.lock`（`fs.openSync(path, "wx")` 创建，含 `{ pid, startedAt }`，带 `process.kill(pid, 0)` 死进程检测与 30s 超时恢复）保证跨子代理控制转换的严格原子性。

### 3.1 看板权威数据模型与责任集合 $R(a)$

`board.json`（带单调递增 `board_version`）维护四张表，每次变更同步向 `events.jsonl` 追加事件：

1. **`tasks`**：`{ task_id, ledger_key, goal, remaining_work, done_when, state: "ready" | "waiting" | "done", wait_for: string[], needs_token: boolean, owner_id: string | null, claim_id: string | null, parent_id: string | null, child_ids: string[], result_refs: object[], handoff_note: string }`。取消与替代只记入事件日志并从活动树移除叶子，不设 `"cancelled"`/`"replaced"` 任务状态。
2. **`actions`**：`{ action_id, task_id, agent_id, claim_id, kind: "board" | "edit" | "shell", phase: "claimed" | "waiting-gate" | "applying" | "running" | "finished" | "uncertain", request_id, result_ref }`。相同 `request_id` 幂等重放原结果，同 ID 异载荷立即拒收。
3. **`actors`**：`{ agent_id, slot_id, role: "normal" | "holder", life_state: "alive" | "dead" | "terminated", active_action_id: string | null }`。`slot_id` 固定复用，`agent_id` 永不复用。
4. **`token_slot`**：`{ holder_id: string | null, term_id: string | null, state: "free" | "held" }`。每 worktree 唯一。

**责任集合公式**：设 $U$ 为所有 `state` 处于 `"ready"` 或 `"waiting"` 的任务集合，个体 $a$ 的完整未结责任集合为：
$$R(a) = \{t \in U \mid \neg t.\text{needs\_token} \land t.\text{owner\_id} = a\} \;\cup\; (\text{if } \text{holder\_id} = a \text{ then } \{t \in U \mid t.\text{needs\_token}\} \text{ else } \emptyset) \;\cup\; \{e \in \text{actions} \mid e.\text{agent\_id} = a \land e.\text{phase} \in \{\text{"applying"}, \text{"running"}, \text{"uncertain"}\}\}$$
处于 `"waiting"` 的任务与仍在运行的 `bash` 会话均计入 $R(a)$，严禁将其折算为无责。

### 3.2 看板协调工具与父项保留实质规则

蜂群个体通过以下单对象参数工具操作看板（全部在 `board.lock` 内短事务完成，耗时 < 5ms）：

1. **`board_split({ parent_id, expected_cond, children, remaining_work, wait_for })`**：
   * 拆分优先于认领。创建子项、写入 `wait_for`、强制要求非空的父项后续合龙说明 `remaining_work`，并将父项置为 `"waiting"`。若并发个体已先一步拆分，返回冲突及最新任务树供增量补充。
2. **`board_claim({ task_id, atomicity_reason })`**：
   * 仅用于已不可再拆出独立价值子项的原子工作。核验调用者 `:alive`、任务 `"ready"`、无冲突认领、普通归属匹配且令牌资格相符（`:needs-token` 任务仅当前 `Holder` 可认领执行），签发唯一 `claim_id`。
3. **`board_finish({ task_id, claim_id, result_summary, dependency_paths })`**：
   * 若 `dependency_paths` 非空（或本会话 `read-set` 非空且结论依赖文件事实），先获取写锁 `$W$` 复核全部相关文件 `stamp` 未变，再进入看板锁提交。
   * 将任务置为 `"done"`；检查所有直接等待它的父项——若某父项的 `wait_for` 已全部 `"done"`，**仅将该父项从 `"waiting"` 切换回 `"ready"`（保留原 `owner_id` 与 `remaining_work`），绝不自动标为 `"done"`**。
   * **防顺手关父项硬门禁**：若父项在本轮事务中刚由子项完成而解除 `"waiting"`，下一次针对该父项的 `board_finish` 必须来自一次新的独立核验回合且附带合龙证据，严禁子项与父项同回合连带秒关。
   * 事务末尾按最终状态重算 $R(\text{holder})$ 与全局可推进集：若 $R(\text{holder}) = \emptyset$ 则同事务执行持令者退休；若全部根任务 `"done"` 且无在途动作，同事务触发 §2.4 接力屏障。
4. **叶子维护动词**：`board_cancel`（仅限无未完子项的叶子）、`board_replace`（原子替换叶子并改挂父项 `wait_for`）、`board_release`（进入 `applying` 前释放认领）、`board_reopen`（`"done"` → `"ready"` 并广播唤醒）、`board_comment`、`board_update`。
5. **`board_park_slot({ observed_board_version })`**：
   * **全局禁主动休眠**：只要全看板仍存在任何非阻塞可推进工作（哪怕该工作只能由 `Holder` 执行或已被他人认领准备中），一律拒收休眠请求并返回可观察工作摘要。仅当全局可推进集合确实为空（如全员等待唯一阻塞中的 `bash` 返回）且 `observed_board_version` 仍为最新时才登记休眠；任何使可推进集变非空的看板提交或人类新输入立即 `wake-all`。

### 3.3 `take_or_die` 不可逆令牌竞争与只读 `Blocker Oracle`

1. **`board_take_or_die({ request_id, confirm })`**：
   * `confirm` 必须精确等于 `"i-hereby-confirm-i-die-without-regret"`，否则拒收 `:CONFIRMATION_REQUIRED`。调用者当前不得有在途 `applying`/`running` 动作，且手头普通责任须已写明 `handoff_note`。
   * **获胜（`:attempt-won`）**：当 `token_slot.holder_id === null` 时，同事务将调用者升为 `"holder"`，签发新 `term_id`（若竞态下此时 $R(a)=\emptyset$，同事务紧接执行无责退休）。
   * **落败（`:attempt-lost`）**：当令牌已被抢占时，同事务解除调用者全部认领、将其普通任务（含 `"waiting"` 父项）的 `owner_id` 置 `null` 归还公共池、将其 `life_state` 置为 `"dead"`。内核随即中止该子代理进程，并在该 `slot_id` 启动全新 `agent_id` 与空白上下文。
   * 严格满足并发交错不变量 **T01–T13** 与控制性质 **V01–V08**。
2. **只读 `Blocker Oracle`（异构主模型死结会诊）**：
   * 当某个任务被连续 `reopen` / `release` 达 2 次，或 `Holder` 验证同一问题连续失败时，内核按 `(goal, done_when, normalized_reason)` 计算阻塞指纹 `fingerprint`。
   * 若该指纹尚未会诊过，内核自动通过 `runSubprocess` 启动一次主模型只读会话（工具仅限 `read`/`search`/`find`），将产出的具体替代步骤作为 `board_comment` 写入该任务，避免 `@task` 模型在死胡同里无限转世消耗额度。

### 4.2 纳秒级 `stamp` 采集与写入口 $W$ 提交协议

1. **无锁读取登记**：
   * 在 `tool_execution_end` 拦截成功的 `read` 调用，使用 `fs.lstatSync(absPath, { bigint: true })` 读取 `{ mtimeNs: stat.mtimeNs, size: stat.size, isSymbolicLink: stat.isSymbolicLink() }`（拒绝符号链接越界，完全忽略 `atime`）。
   * 若工具执行前后两次 `lstat` 不一致，立即在返回结果附加 `:changed-during-read` 警告且不记入稳定依据；稳定读取记入当前 `agent_id` 的内存 `readSet`（目录列表 `ls`/`find` 仅作纯探查，不进 `readSet`）。
2. **写锁 $W$ 内的 `stamp` 复核与保护落盘**：
   * 在 `tool_call` 拦截 `write` 或 `edit` 时：
     1. 核验当前 `agent_id` 在看板中仍 `:alive` 且持有有效活动 `claim_id`；
     2. 获取当前 worktree 的排他写锁 `$W$`（`.herd/locks/<slice_id>.write-w.lock`）；
     3. 在 `$W$` 保护下，复核目标文件（若已存在则必须已在 `readSet` 中；新建文件则必须确认目标当前不存在）及本轮声明依赖文件的当前 `{ mtimeNs, size }` 是否与 `readSet` 完全相等；
     4. **触盘前拒绝**：任一 `stamp` 不匹配或路径类型冲突，立即释放 `$W$` 并返回 `{ block: true, reason: ... }`（使用 UFSS 格式列出 `:FILE_CONFLICT` 路径、原 `stamp` 与当前 `stamp`），真实磁盘零修改；
     5. **原子写与锁释放**：核验通过后在看板登记 `:applying` 资格，放行底层写入（对于整文件写入统一走同目录 `.tmp` + `rename` 原子替换），在紧随其后的 `tool_execution_end` 更新该会话 `readSet` 的最新 `stamp`、完成看板记账并立即释放 `$W$`。

### 4.3 `Holder` 黑盒 `bash` 生命周期

1. **持令等待不占写锁**：`Holder` 仅在单次 `bash` 实际执行期间持有 `$W$`；两次 `bash` 之间阅读、拆分或等待 `Worker` 改代码时**绝不占用 `$W$`**，普通个体的 `write`/`edit` 畅通无阻。
2. **启动前二次核验**：`bash` 排队取得 `$W$` 后、真正派生子进程前，在短看板锁内再次核验 `holder_id === caller`、`term_id` 未过期且关联任务仍有效，登记 `:running` 活动责任。
3. **输出有界与取消核对**：单次 `bash` 内联返回上限默认 **1 MiB**，完整日志写入 `.herd/artifacts/`（单会话上限 **64 MiB**，超出显式标 `:output-truncated`）。若执行期间遭遇操作员 `Esc` 取消或进程异常中断，动作如实标为 `:cancelled`（确认未启动）或 `:outcome-unknown`（已启动可能产生外部副作用），绝不盲目自动重跑非幂等命令。

## 5 消息投影、`Scope` 上下文管理、缓存对齐与 UFSS 呈现

### 5.1 系统提示词拼装

在 `before_agent_start` 中按角色纯文本静态拼接，不含随机动态字段（确保系统提示词字节恒定）：
* **语言与内省底线**：强制以简体中文思考（尤其思考首词必须为简体中文词），强制以简体中文面向用户输出；每次工具调用前在内部完成三闸门自检（现状核对、方向追问、主动证伪）。
* **阶段方法论纪律（`METHOD_DISCIPLINE`）**：按当前所处 S1（Howard/Dalio/Bezos）、S2（Bach/Myers/Weinberg）、S3（Pólya/Schoenfeld）、S4（Knuth）及全阶段 Goodhart 守卫注入；规定只有当某个方法切实改变了决策或检查项时才可点名引用，严禁拿大师名字做空洞背书。
* **Scope 完整规则**：只在基础提示词中完整讲一次，工具参数 Schema 只留字段形状与一句短说明。

### 5.2 Wire Schema 协议门（`tool-gate`）：`:scope` + 语言锚点

`src/tool-gate/index.mjs` 在 `before_provider_request` 为请求体中每个非豁免工具的 JSON Schema 动态注入两个必填字段，并在 `tool_call` 执行前完成校验、记账与剥离（底层工具收不到这两个字段）：

1. **`must_think_in`**：`{ type: "string", enum: ["zh-cn"] }`，在解码层锁死中文推理轨道。
2. **`scope`**：打平的上下文所有权注解对象，`kind` 精确四选一：
   * `"resetScope"`：必填 `new_scope_goal`（非空字符串）与 `new_scope_retention_budget`（正整数，无上限），开启新闭环并重置预算；进程冷启后首个非豁免调用必须为 `"resetScope"`（否则拒收 `:SCOPE_UNINITIALIZED`）。
   * `"keepLast"`：无额外字段，认可上一拍成果，扣减 1 点 `retention`。
   * `"removeLast"`：必填 `replacement`（非空字符串），抹除上一拍探索弯路（不扣 `retention`），在出站投影中将上一拍工具调用、思考与结果替换为一条写明经验教训的简短消息。
   * `"meToo"`：无额外字段，同一模型回合内多工具并发调用的附议；若整回合全为 `"meToo"`，回合末默认按 `"keepLast"` 结算并扣 1 点 `retention`。当 `retention === 0` 时，除 `"resetScope"` 与豁免工具外一律在准入阶段拒收 `:SCOPE_BUDGET_SPENT`（工具不执行）。
3. **豁免与钉住工具**：
   * `ask_previous_scope({ questions })`：不扣 `retention`，向紧邻前一个归档 Scope 发起只读查询，同步返回受理回执，答案以 `steer` 消息异步送达；调用与结果跨 `resetScope` 永久保留。第二次及以后的 `resetScope` 须按“先 `ask_previous_scope`（按需）、后 `resetScope`”分步调用。
   * `assume({ assumption })`：将已抽象的关键引理钉住，返回固定确认语；跨 `resetScope` 豁免历史裁除，但不豁免当拍 `retention` 扣减。
4. **出站请求副本裁剪（零历史污染）**：
   * 在 `context` 钩子中，系统不修改宿主 `sessionManager` 持久化的任何条目，仅构造出站消息数组副本：最新已结算 `"resetScope"` 边界之后原样保留；边界之前只保留人类操作员消息、历次 `"resetScope"` 调用与配对回执、`assume` 与 `ask_previous_scope` 调用及回执、以及助手结论正文，其余过期工具大输出与 thinking 块全部从出站副本裁除。

### 5.3 双块锚点缓存保留与显式断点前移

为同时最大化隐式前缀缓存（OpenAI / DeepSeek）与显式断点缓存（Anthropic / Bedrock）命中率：
1. **稳定块与易变块分离重放（`LiveTailRetention`）**：注入模型尾部的实时上下文拆为**稳定状态块**（当前阶段协议、冻结契约摘要、看板 clean-break 全量快照）与**易变增量块**（运行耗时、剩余 `Scope` 预算、其他个体产生的看板增量 `delta`）。当某 agent 自己写入看板时，触发其个人视图 **clean-break**（清除旧 `delta` 换上最新全量看板快照）；当只是其他个体改看板时，仅在历史锚点后追加小 `delta`（最多保留 32 条 / 4 KiB），保证连续请求的会话前缀逐字节稳定。
2. **显式缓存断点前移**：在 `before_provider_request` 中，若检测到宿主在末尾瞬态注入块上打了 Anthropic `cache_control` 或 Bedrock `cachePoint`，自动将该标记前移至紧邻的最后一个真实持久历史块，绝不增加额外断点数量，完整保留宿主配置的 TTL。
3. **上游瞬态故障退避**：在 `agent_end` 区分真实用户取消（`ctx.signal?.aborted`）与上游断流（无用户信号却返回 `aborted`、HTTP 429、502/503/504/529、`network_error`）；排除 `insufficient_quota`/账单耗尽后，对瞬态故障按 `5s → 10s → 20s → 40s → 80s` 指数退避自动恢复。

### 5.4 面向模型的 UFSS（Universal Fence-Scaled String）输出规范

凡本插件生成的工具回执、看板快照与冲突诊断，一律采用 EDN + UFSS 变长围栏字符串渲染，严禁向模型返回充斥 `\"`、`\\`、`\n` 的 JSON 转义字符串：
* 不含 `"`、`\`、换行与控制字符的短文本输出普通 `"..."`；
* 含 `"` 或 `\` 的单行文本（如代码锚点、正则表达式、Windows 路径），取最小正整数 $n \ge 1$ 使 `"#^n` 不在正文中出现，输出 `#^n"..."#^n`（如 `#"C:\work\a.mjs"#`），反斜杠原样保留零转义；
* 多行文本（如源码片段、终端日志、契约章节），取最小非负整数 $n \ge 0$ 使 `"""#^n` 不在正文中出现，输出独立缩进块 `#^n"""\n...\n<indent>"""#^n`（读取语义自动剥离结束行左侧公共空格缩进 `<indent>`，与原始字符串构成严格数学双射）；
* 含 `\r`、`\0` 等不可见控制字符时回退显式 `\r`、`\uXXXX` 转义，杜绝隐形字符污染。

#### 二、 技术关键点：不用 JVM，如何在 .mjs + ClojureScript 中实现表达式级 where/park/unpark 与沙箱？

在纯 JS/Bun 环境里做这件事，如果直接用同步解释器（如默认 sci/eval-string），遇到嵌套在 (let [[b e] (where ...)] ...) 或 (mapv (fn [p] ... (where ...) ...) paths) 里的挂起会直接卡死在同步调用栈上；而如果直接把 ClojureScript 编译成裸 JS eval()，模型写一句 (js/process.exit 1) 或访问 globalThis 就会击穿角色只读沙箱。

最干净、零 JVM 的工程解法是：**引入单一轻量 ESM 依赖 cherry-cljs（提供正宗 ClojureScript 不可变持久集合、Keyword、Symbol、结构相等 =、cljs.core、clojure.string、clojure.set、clojure.walk 与 EDN Reader）+ 自建约 350 行 .mjs 的「隔离环境 Promise-CPS 异步求值器」**：

1. **UFSS 预读取器 + cherry-cljs EDN AST**：先用确定性扫描器处理 #^n"..."#^n 与 #^n"""..."""#^n（执行五步缩进剥离并保留精确源码行号供 :source 回执展示），再交由 ClojureScript Reader 读成带行列元数据的不可变表单（Forms）。
2. **物理隔离沙箱（Air-Gapped Symbol Table）**：求值器的符号表只绑定纯函数版的 cljs.core / clojure.string / clojure.set / clojure.walk、支持异步顺序求值的高阶序列函数（map/mapv/keep/filter/reduce/doseq 等），以及当前角色的专属单 map 能力集（clj-plan / clj-review / clj-worker / clj-devops / clj-auditor）。js/*、globalThis、process、Bun、require、import 在符号表中根本不存在，从根源上杜绝越权 I/O。
3. **利用 JS 原生未决 Promise 保存表达式级续体（Continuation）**：求值器每一步都是 async 的。当执行到任意深度的 (park ...)、0 匹配或多匹配的 (where ...)、S1 的 (ask ...) 或 :intent 计时到期时，能力函数在内存 ParkedPrograms 表中登记一个未决 Deferred = { resolve, reject, receipt }，同时触发外层 parkSignal 竞争返回。此时外层工具调用**立即向大模型返回 EDN + UFSS 挂起回执**，而该 defprogram 的整个 JS 异步调用帧（含所有外层 let 局部变量、loop 状态与尚未提交的**批内 VFS 内存修改视图**）原封不动悬停在内存中，不占写锁 $W$、不落盘！当后续程序调用 (unpark {:name "fix-timeout" :value [812 842]}) 并通过四道防呆核验后，直接调用 deferred.resolve([812, 842])，原挂起表达式瞬间拿到 [812 842] 继续往下跑完 write，正常返回后进入 $W$ 锁内 stamp 复核与原子落盘！

## 1 十条硬约束（不变量铁律）

以下十条是全系统的最高不变量。后文章节展开实现细节；若细节与本节存在任何歧义，以本节为准：

1. **极简依赖、零宿主猴子补丁、多入口故障隔离。** 运行时除 `omp` 宿主自带包外，仅允许依赖纯 JS/ESM 的 `cherry-cljs` 提供 ClojureScript 不可变数据结构与核心函数库；严禁依赖 `pi-goal-x` 或 `pi-context`，严禁篡改宿主类原型。`package.json` 声明独立清单入口（主装配入口、`tool-gate` 协议门入口），任一入口异常不得导致其余入口或宿主崩溃。
2. **五阶段严格递进与渐进式 SHA-256 契约冻结。** 使命依序推进 **S1（头脑风暴）→ S2（手工测试方法论）→ S3（目标导向开发指南）→ S4（开发者协调手册）→ S5（蜂群自治开发）**。每一阶段封板晋级时，内核立即计算该阶段文档的 `sha256` 并冻结；后续阶段与 S5 执行层对已冻结文档严格只读。若人类直接修改了 `plans/<slug>/` 下的文档，`stamp`/哈希冲突以人类版本为准触发对齐，严禁覆盖人类意图或拿失配契约结案。（见 §2.2）
3. **宏观中心化换任与微观去中心化蜂群严格咬合。** S5 每个 Slice 任期以中心化评估窗口（Phase A）开启：单一主模型 `Reviewer` 用只读 `clj-review` 核验现场并提交 `(review {:findings [...]})`；若台账非空，`Reviewer` 退场、生成看板根任务并唤醒 `@task` 蜂群（Phase B）通过 `clj-worker` 并发施工；仅当看板全部根任务 `:done` 且无在途动作时，原子触发接力屏障（退休本任、写入上下文屏障、唤醒无前任对话包袱的新任 `Reviewer`）。S1–S4 规划期非空台账由 `Plan` 自己销账，不开蜂群。（见 §2.4）
4. **父项始终保留实质，严禁子项完成自动关闭父项。** 看板中拆分优先于原子认领；父任务 `split` 出子项后进入 `:waiting`，子项全部 `:done` **仅解除父项等待使其恢复 `:ready`**，绝不自动折算为父项 `:done`，且严禁在解除等待的同一批次中顺手关闭父项。父项必须由负责个体完成合龙验证后显式 `finish`。（见 §3.2）
5. **文件写入一律走受保护提交合同（批内 VFS 干跑 + 纳秒 `stamp` + 写入口 $W$）。** `cat`/`stat` 不加锁，自动采集精确凭据 `stamp = {:mtime-sec <int> :mtime-nsec <int> :size <int>}`（忽略 `atime`）。`defprogram` 内的 `write`/`mkdir`/`rm`/`mv` 先作用于批内内存 VFS 视图；仅当程序正常返回（或 `call` 前排空）时，才申请 worktree 写锁 $W$，锁内复核全部 `read-set`（含只读依赖文件）与结构条件，固定 `:applying` 资格后一次性原子落盘。任何可拒绝冲突必须在触碰真实磁盘前拒绝，正常路径零回滚。（见 §4.2）
6. **抢令牌（`take-or-die`）不可逆，持令者独占 `call` 且无责即死，新生无记忆。** 普通个体调用 `(call ...)` 一律拒收 `:TOKEN_REQUIRED`。个体仅在耗尽有价值的受保护工作且存在未结 `:needs-token` 任务时调用 `(take-or-die {:request-id ... :confirm :i-hereby-confirm-i-die-without-regret})`：赢者成为唯一 `Holder`，动态承担全部 `:needs-token` 责任（仅在实际运行 `call` 或提交文件时占 $W$，等待期释放 $W$）；输者在同一看板锁事务内公开移交剩余责任与认领并逻辑死亡；`Holder` 在完整责任集合 $R(a) = \emptyset$ 时同事务释放令牌并逻辑死亡。槽位随后通过 `runSubprocess` 启动全新 `agent-id`，绝不继承前世上下文。（见 §3.3）
7. **常授权无人值守（Nudge 胜出，配空转退避）与 Esc 递归取消。** 默认 `/herd` 模式下合法停止出口仅三个：S1 调用 `(ask {:question ...})` 挂起等人类回答；S5 初任 `Reviewer` 首次空账且工作区已满足契约时转为一次性 `ask`；S5 独立实操审计全部达标结案。其余时刻结束回合自动注入 Nudge（连续无实质进展时按 `30s→300s` 指数退避）。系统无暂停态；操作员按 `Esc` 时，取消信号沿主会话与整棵 `runSubprocess` 子会话树递归传播，外部动作如实记为 `:cancelled` 或 `:outcome-unknown`。（见 §2.5）
8. **规划期只读边界与唯一调查原语 `devops`。** `Plan` 顶层代理除当前阶段的 `plans/<slug>/s1..s4-*.md`（且须在本任首次 `review` 解锁后）外无任何写入能力；调查仓库事实只能调用同步原语 `(devops {:verbose-intent "..."})`，复用同一任期专属只读 `Plan DevOps` 子代理并原样返回其最终报告。（见 §2.2、§4.1）
9. **模型归属、独立实操审计与反自动化教条。** `Plan`、中心化 `Reviewer`、S5 `Manual Auditor` 与只读 `Blocker Oracle` 使用主模型（Main Model）；`Plan DevOps`、蜂群普通 `Worker` 与 `Holder` 一律使用用户配置的 `@task` 模型。一切子代理经 `runSubprocess` 持久化产物并在 Agent Hub 实名可见。任何自动化测试、单测、CI 或构建通过均不构成 S5 验收证据。（见 §2.1、§2.4）
10. **系统呈现一律 EDN + UFSS，出站 `Scope` 投影不涂改历史。** 系统面向大模型的一切结构化呈现（工具回执、挂起诊断、看板增量/快照、冲突详情）一律使用 **EDN + UFSS（`#"..."#` 与 `#"""..."""#`）**，严禁投喂带转义噪音的裸 JSON；模型提交支持 EDN+UFSS、标准 Clojure 字符串与外层 JSON 工具信封。每个非豁免工具调用必带 `:scope` 与中文思考锚点，裁剪仅作用于 `context` 出站副本，绝不改写宿主 `.jsonl` 会话文件。（见 §5.2、§5.4）

## 2 宏观秩序：五阶段方法论（S1–S5）、换任接力与多 Worktree 编排

### 2.1 角色谱系、沙箱工具与模型归属

使命激活期间，插件通过 `pi.setActiveTools` 与子代理工具表将模型可用工具收敛至对应角色的专属沙箱工具（封禁宿主裸 `write`/`edit`/`bash`/`read` 绕过路径）：

| 角色身份 | 所在阶段 | 专属工具面 | 职责与边界 | 模型归属 |
|---|---|---|---|---|
| `Plan` | S1–S4 规划期 | `clj-plan` + Scope 辅助 | 打磨 `plans/<slug>/s1..s4-*.md`；首评前写锁；仅 S1 可 `(ask ...)`；靠 `(devops ...)` 调查仓库；非空 `review` 自销账。 | 主模型（Main） |
| `Plan DevOps` | S1–S4 辅助层 | `clj-devops` | 每任 `Plan` 专属一个，无看板、无令牌；持只读文件探查与 best-effort 只读 `call`，返回完整调查报告；同任期复用/steer。 | 任务模型（`@task`） |
| `Reviewer` | S5-Phase A | `clj-review` + Scope 辅助 | 每任期中心化主审。只读核验契约与 worktree 现场，提交首评 `(review {:findings ...})`：空账晋级/入队，非空立账开蜂群。 | 主模型（Main） |
| `Swarm Worker` | S5-Phase B | `clj-worker` + Scope 辅助 | 无中心自治个体。优先 `split` 拆分、认领原子任务、经批内 VFS + `$W$` 提交修改；调 `call` 拒 `:TOKEN_REQUIRED`。 | 任务模型（`@task`） |
| `Swarm Holder` | S5-Phase B | `clj-worker` + Scope 辅助 | 经 `take-or-die` 获胜的唯一持令者（每 worktree 至多 1 名）。执行 `:needs-token` 的黑盒 `call` 与 Git `rebase`，无责同事务即死。 | 任务模型（`@task`） |

### 2.2 五阶段大师方法论与交付契约（S1 → S2 → S3 → S4 → S5）

所有阶段交付物位于仓库根目录 `plans/<slug>/` 下（`<slug>` 匹配 `^[a-z0-9][a-z0-9-]{0,63}$`）。**阶段判定铁律**：每个阶段只判定“离下一阶段能够开始的差距”，严禁把后续阶段的工作算作本阶段缺口；每一任 `Plan` 在提交本任首次 `review` 前对当前阶段文件只读（`:WRITE_LOCKED_BEFORE_FIRST_REVIEW`），首次 `review` 后才解锁写入。

#### S1：头脑风暴与需求决策（Bezos · Howard · Dalio · Munger · Taleb）
* **唯一交付物**：`plans/<slug>/s1-brainstorm.md`。
* **方法论矩阵**：
  * **Jeff Bezos（逆向工作法）**：从最终用户可见结果倒推，先写清发布稿（Press Release）、核心 FAQ 与单向门 / 双向门分类（单向门决策要求强证据，双向门在 70% 信息时快速决断）。
  * **Ronald A. Howard（决策分析）**：显式拆开决策框架（Frame）、目标（Objectives）、备选方案（Alternatives）、信息（Information）与价值权衡（Values），先算清进一步调查的信息价值（VoI）。
  * **Raymond Thomas Dalio（极度求真）**：直陈当前最痛的事实与约束，深挖根因（Root Cause）而非表象，按实证可信度加权判断。
  * **Charlie Munger（反向思考 / 事前验尸）**：反过来追问*“如果这项工程最终一败涂地，最可能是哪三条假设错了？”* 并建立前置防线。
  * **Nassim Nicholas Taleb（否定法 Via Negativa）**：明确列出“刻意不做的事（Non-Goals）”与必须砍掉的脆弱耦合，用减法锁定真实意图。
* **S1 唯一提问通道**：仅在 S1 允许调用 `(ask {:question "..."})` 挂起程序并交还人类操作员回答，人类回复后通过 `(unpark {:name ... :value ...})` 原地恢复。

#### S2：手工测试方法论（Bach · Myers · Weinberg）
* **唯一交付物**：`plans/<slug>/s2-manual-tests.md`（写入时强制执行语法解析与结构校验，不合规直接拒收）。
* **方法论矩阵**：
  * **James Bach（Rapid Software Testing：Testing $\neq$ Checking）**：机器自动化脚本（单元测试、集成测试、Linter、Typecheck、CI）只是对局部旧假设的机械核对（Checking），**严禁作为验收证据**；验收必须是对真实运行系统、真实终端（tmux 按键抓屏）与真实产物的探索性实操检验（Testing）。
  * **Glenford J. Myers（证伪导向与破坏性覆盖）**：测试的唯一目的是发现错误而非证明无错，且执行者绝不能自证完成。用例必须覆盖正常、非法输入、边界极值、并发交错（写锁冲突、抢令竞态）、环境/依赖缺失（`/tmp` 隔离破坏实验）、取消中断与崩溃恢复，严禁缩水为 Happy Path。
  * **Gerald M. Weinberg（质量即利益相关者价值 → 双视角 WTP 可复现细则）**：文档中每个 `### CASE-*` 必须包含：
    1. `- PASS threshold: N/100`（$0 \le N \le 100$）；
    2. `- 路径：<类别>`；
    3. `- 评分细则：...`——将可观察实操证据映射到完整 `0–100` 区间，明确及格线与差一档不及格的证据分界、Hard-fail 一票否决项、漏测异常分支扣分项与取整粒度，确保两独立审计员面对同一证据分差 $\le \pm 5$（严禁写空洞形容词或套用权重模板）；
    4. **双视角主观支付意愿（WTP）**：S5 审计员须独立给出 `user_score`（外部用户愿付费程度，0–100）与 `developer_score`（内部工具开发者愿付费程度，0–100），最终分取 `min(user_score, developer_score)`，任一低于阈值即 FAIL。

#### S3：目标导向开发指南（Pólya · Schoenfeld · Parnas · Hickey · Ousterhout）
* **唯一交付物**：`plans/<slug>/s3-dev-guide.md`（须包含模块边界、单向依赖图与实现步骤）。
* **方法论矩阵**：
  * **George Pólya（解题四步）**：通过 `(devops ...)` 摸清宿主与代码全貌后，制定从最小完整件（Gall 定律 + Mise en place 备料）出发的分步演进计划。
  * **Alan H. Schoenfeld（元认知监控与调控）**：盘点宿主边界（Chesterton's Fence），建立过程止损规则——当某条技术路径连续无法产出可验证证据时立即切换方案，拒绝为沉没成本辩护。
  * **David L. Parnas（信息隐藏）**：严格按“可能独立变化的设计秘密”划分模块，严禁按时间流水账或文件行数切分模块。
  * **Rich Hickey（解耦与值导向）**：分离不可变数据（Values）、显式状态转换（State）与职责身份（Identity），杜绝多职责纠缠（Complecting）。
  * **John Ousterhout（深模块与消解异常）**：设计“窄接口、深实现”的模块，通过前置防呆（Poka-yoke）在接口层消解非法状态，而非到处散落防御性补丁。

#### S4：开发者协调手册（Knuth · Brooks · Lamport · Amdahl）
* **唯一交付物**：`plans/<slug>/s4-coordination.md`（须包含文学化伪代码、不变量表、无环 Slice 切片表与合并顺序）。
* **方法论矩阵**：
  * **Donald E. Knuth（文学化伪代码）**：在写任何实现代码前，用精确伪代码定死核心数据结构、状态字段与转换步骤。
  * **Frederick P. Brooks Jr.（反制人月神话）**：将工程切分为目标**互不相交（Disjoint）**的 `Slices`（`{:slice-id :goal :inputs :depends-on :done-when :cases}`），靠前置契约与独立 worktree 把跨组沟通开销降为 $O(1)$。
  * **Leslie Lamport & Edsger W. Dijkstra（并发 Safety 与 Liveness）**：显式列出并发安全性不变量（互斥、幂等、死身份禁写）与活性条件（无死锁、无睡死、Quiescence 收束）。
  * **Gene Amdahl & Donald G. Reinertsen（压薄关键路径与队列流）**：识别并压薄串行关键路径与全局锁持有区间，禁止人为分批等待（Artificial Waves），上游契约一就绪立即放行下游，最小化总墙钟耗时。

#### S5：契约冻结、蜂群自治开发与终局实操验收
* S4 经继任审阅空账（或 `/herd-pair` 人类批准）通过后，内核计算 `s1..s4` 四份文档的 `sha256` 冻结写入 `.herd/missions/<slug>/mission.edn`，正式进入多 Worktree 蜂群开发与 `Manual Auditor` 实操验收，最终原子产出 `plans/<slug>/s5-report.md`。

### 2.3 多 Worktree Slice `fork` / `join` 队列编排

1. **互不相交派发**：内核按冻结的 `s4-coordination.md` 拓扑，为所有 `:depends-on` 已满足的 Slice 在 `.herd-worktrees/<slug>/<slice-id>` 创建独立 Git worktree，每个 Slice 拥有独立的看板、令牌槽与写锁 `$W$`，绝不把同一份活重复派给多个 Slice。
2. **FIFO `join` 队列与串行 `--ff-only` 集成**：
   * Slice 内继任 `Reviewer` 空账确认合格且通过单任期 Quiescence 检查后，该 Slice 进入完成队列；
   * 内核按完成先后（FIFO）逐个取出 Slice，获取**主分支集成锁**；若目标主分支已前进，唤醒该 Slice 的 `Holder` 执行 `git rebase`（若因架构淘汰存在不可解冲突，`Holder` 调用 `(abandon {:reason ...})` 丢弃该 worktree）；
   * 对齐后主分支执行机械 `git merge --ff-only`，释放集成锁，并解锁依赖该 Slice 的后续 Slice。Worktree 在结项后默认保留 7 天再自动清理。

### 2.4 Slice 任期双相循环与 S5 终局可见实操审计

1. **Slice 内双相循环（Phase A `Reviewer` ⇄ Phase B `Swarm`）**：
   * **Phase A**：干净子会话运行主模型 `Reviewer`（持只读 `clj-review`）。若提交非空 `(review {:findings [{:key "k1" :value "v1"} ...]})`，内核在同一看板锁内关闭评估窗、将每条义务转为根任务 $T_k$（`:state :ready`）并拉起 `@task` 蜂群槽位；
   * **Phase B**：蜂群围绕看板并发拆分、认领、受保护写文件与持令验证；根任务 $T_k$ 显式 `finish` 时同步解除台账键 `k`；
   * **原子接力屏障**：当全部根任务 `:done`、$U = \emptyset$、无在途动作且 `Holder` 已无责退休时，原子将本任标为 `:retired`、建立上下文屏障切掉前任全部对话，启动无包袱 `:successor` `Reviewer`。继任者首评提交空账 `[]` 即确认本 Slice 合格入队；提交非空 `findings` 则打回开启新一轮蜂群。
2. **全局终局实操审计（`Manual Auditor`）**：
   * 全部 Slice 合入主工作区后，内核校验 `s1..s4` 四枚 `sha256` 未变，通过 `runSubprocess` 启动实名可见的 `Manual Auditor`（主模型，`clj-auditor`，硬超时 60 分钟，Agent Hub 全程可见）。
   * 审计员按 `s2-manual-tests.md` 顺序亲自实操全部 `CASE-*`（TUI 交互必须在 `tmux` 真按键抓屏存至 `plans/<slug>/evidence/`；破坏性分支必须在 `/tmp` 副本执行），最后调用 `(submit-audit {:report-markdown #"""..."""# :scores [{:case-id "CASE-01" :user-score 95 :developer-score 92} ...]})`。
   * 审计结束后内核再次复核 `s1..s4` 哈希未变，独立计算每个 CASE 的 `min(user_score, developer_score)`：全部达标则原子写出 `plans/<slug>/s5-report.md` 并签发绑定 `(missionId, revision)` 的结案批准令；任一未达标则输出失败明细，将未过 CASE 转为返工根任务继续推进。

### 2.5 常授权无人值守（Nudge + 空转退避）与结对双轨

* **`/herd <seed>`（默认无人值守）**：除 S1 `ask`、S5 初任空账 `ask` 与 `s5-report.md` 全 PASS 结案外，绝不等待人工审批。非出口结束回合由内核自动注入 Nudge 督促消息。若本轮有实质状态推进，0ms 立即续跑；若连续无实质推进，首轮立即续跑，随后按 `30s → 60s → 120s → 240s → 300s` 指数退避，看板变更或人类新消息到达立即清零退避。
* **`/herd-pair <seed>`（结对门禁）**：S1–S4 每阶段文档落盘并通过自审后挂起等待人类明确批准再晋级，S5 全程自治开发与实操审计。

## 3 微观蜂群执行层：文件锁看板、拆分优先与 `take-or-die`

每个活动 worktree 的控制状态保存在 `.herd/missions/<slug>/slices/<slice-id>/board.edn`（及追加式事件账本 `events.jsonl` + UTF-8 字节偏移检查点），由同目录排他锁 `.herd/locks/<slice-id>.board.lock`（`wx` 原子创建 + PID 存活探测 + 30s 陈旧锁恢复）保证短事务原子性。

### 3.1 看板权威记录与责任集合 $R(a)$

* **`Task`**：`{:task-id :ledger-key :goal :remaining-work :done-when :state (:ready|:waiting|:done) :wait-for #{} :needs-token :owner-id :claim-id :parent-id :child-ids :result-refs :handoff-note}`。
* **`Action`**：`{:action-id :task-id :agent-id :claim-id :kind (:board|:edit|:shell) :phase (:claimed|:preparing|:waiting-gate|:applying|:running|:finished|:uncertain) :request-id :result-ref}`。
* **`Actor`**：`{:agent-id :slot-id :role (:normal|:holder) :life-state (:alive|:dead|:terminated) :active-action-id}`。
* **`TokenSlot`**：`{:holder-id :term-id :state (:free|:held)}`。

个体 $a$ 的完整未结责任集合 $R(a)$ 包含：(1) $U$（`:ready` $\cup$ `:waiting`）中归属 $a$ 的非令牌任务；(2) 若 $a$ 为当前 `holder`，则包含 $U$ 中**全部** `:needs-token true` 任务（后续新增项自动归入）；(3) $a$ 名下处于 `:applying` / `:running` / `:uncertain` 的活动动作。

### 3.2 拆分、认领、父项恢复与禁睡规则

1. **拆分优先 `(split {:parent-id ... :expected-cond ... :children [...] :remaining-work "..." :wait-for #{...}})`**：原子创建子项、写入 `:wait-for`、强制保留非空的父项合龙 `:remaining-work`，并将父项置为 `:waiting`。
2. **原子认领 `(claim {:task-id ... :atomicity-reason "..."})`**：仅对已原子化的当前工作签发唯一 `:claim-id`。
3. **完成与父项恢复 `(finish {:task-id ... :claim-id ... :result-summary ... :read-set [...]})`**：
   * 若结论依赖工作区文件事实（含空写集），先经写锁 `$W$` 复核 `read-set` 的 `stamp`；`finish` 不自动排空批内未提交 `write`，先后顺序严格服从程序书写顺序；
   * 子项置为 `:done` 后，若某直接父项的 `:wait-for` 已全部 `:done`，**仅将该父项从 `:waiting` 恢复为 `:ready`（保留原 `:owner-id` 与 `:remaining-work`），严禁自动置为 `:done`**，且拒绝在同一轮程序内顺手 `finish` 刚恢复的父项；
   * 事务末尾按最终状态重算 $R(\text{holder})$ 与根任务集，原子触发无责退休或任期接力屏障。
4. **维护动词与禁睡**：提供叶子专用的 `cancel`、`replace` 及 `release`、`reopen`、`comment`、`update`。只要全看板存在任何全局非阻塞可推进工作，任何个体调用 `(park-slot {:observed-cursor ...})` 一律拒收；全局为空时同事务核对 `board-version` 登记休眠，新工作或人类输入到达即刻 `wake-all`。

### 3.3 `take-or-die` 生命周期与只读 `Blocker Oracle`

1. **`(take-or-die {:request-id ... :confirm :i-hereby-confirm-i-die-without-regret})`**：
   * 缺失或写错 `:confirm` 拒收 `:CONFIRMATION_REQUIRED`；存在在途副作用动作时拒收协议冲突；相同 `:request-id` 重放幂等返回原结论。
   * **赢（`:attempt-won`）**：`TokenSlot` 空闲时同事务升为 `:holder` 并生成新 `:term-id`（若此时 $R(a)=\emptyset$ 同事务紧接无责退休）。
   * **输（`:attempt-lost`）**：令牌已被占用时，同事务解除全部认领、清空普通责任（含 `:waiting` 父项）的 `:owner-id` 归还公共池、标 `:dead`；内核立即终止该子会话并在原槽拉起全新 `agent-id`（空上下文，无前世记忆）。
   * 完整满足并发交错验收表 **T01–T13** 与控制性质 **V01–V08**。
2. **只读 `Blocker Oracle`**：同一任务或归一化阻塞指纹连续受阻达阈值时，内核自动唤醒一次主模型只读会诊，将替代路径以 `comment` 写入看板，防止 `@task` 模型原地反复转世。

## 4 ClojureScript 沙箱工具面、批内 VFS 干跑与续体恢复

### 4.1 单一语法纪律与各身份能力对照

模型向角色工具（`clj-plan`、`clj-devops`、`clj-review`、`clj-worker`、`clj-auditor`）提交 `(defprogram <program-name> [] ...)`。
**单一写法铁律**：所有能力一律采用**裸函数名 + 单个 EDN map 参数**，无 `this` 绑定，无位置参数。沙箱求值器基于 `cherry-cljs` 不可变数据结构与纯函数标准库运行，物理隔绝 `js/*`、`globalThis`、`process`、`require`、`import` 等一切宿主逃逸入口。

| `(cat {:path ...})` | 读取 UTF-8 文本（优先读批内 VFS 视图，落到底层时自动采集纳秒 `stamp` 记入 `read-set`） | 仅阶段文档与附件 | 有 | 有 | 有 | 有 |

### 4.2 批内内存 VFS 干跑视图与写入口 $W$ 原子提交

1. **无锁读取与纳秒 `stamp`**：首次读取真实文件时通过 `fs.lstatSync(path, { bigint: true })` 提取 `{:mtime-sec <sec> :mtime-nsec <nsec> :size <bytes>}`；单次读取前后 `stamp` 变化立即拒为 `:changed-during-read`。
2. **批内顺序语义与完整预演**：程序内的 `write`、`mkdir`、`rm`、`mv` 仅按执行顺序修改本程序私有的内存 VFS 叠加层（例如先 `mv "a.mjs" "b.mjs"` 再 `cat "b.mjs"` 并 `write "b.mjs"`，后一步直接读到移动后的内容；同路径重复创建、移动成环、删后读取均在内存中拒为 `:PREPARE_REJECTED` 或 `:STRUCTURE_CONFLICT`）。单文件上限 **2 MiB**、单批上限 **16 MiB** / **256** 个路径操作（超限拒 `:LIMIT_EXCEEDED`）。若程序抛错或触发 `park`，**真实磁盘零修改**。
3. **写锁 $W$ 内复核与落盘**：`defprogram` 正常返回（或 `call` 前排空）且存在待提交变更或依赖文件事实的看板发布时：
   * 申请当前 worktree 排他写锁 `$W$`（`.herd/locks/<slice-id>.write-w.lock`）；
   * 在 `$W$` 内复核调用者 `:alive`、`:claim-id` 有效，并逐一比对 `read-set` 全部文件（**含只读依赖文件**）当前磁盘 `stamp` 与 `structure-checks`；任一不符立即释放 `$W$` 并返回 `:FILE_CONFLICT` / `:STRUCTURE_CONFLICT`，磁盘零修改；
   * 在看板锁内固定 `:applying` 资格，按预演确定的最终字节通过同目录排他临时文件 + `fsync` + `rename` 原子落盘，完成纯看板记账后释放 `$W$`。完整满足 **F01–F15** 交错矩阵。

### 4.3 `where` 近似诊断与 `park` / `unpark` 表达式级续体恢复

1. **零匹配与多匹配自动挂起**：
   * `(where {:content src :needle needle})` 要求精确唯一命中。多匹配时自动挂起并返回最多 8 条候选 `{:span [b e] :context "..."}`（前后各 80 UTF-16 码元）；
   * **零匹配 Ukkonen 带状 DP 诊断**：扫描 `content` 前 2000 个非空行，带宽 $K=64$、总 DP 单元预算 10M，返回编辑距离最小的行 `:nearest {:span [b e] :text "..." :distance d}`（无距离 $\le 64$ 的行则为 `nil`）。
2. **Promise 续体保存与四道核验恢复**：
   * 挂起发生时，求值器将当前表达式节点的未决 `Promise` 句柄与尚未提交的批内 VFS 视图保存在本 `agent-id` 内存 `ParkedPrograms` 表中（进程重启自动清空，不入看板），立即返回完整挂起回执（含带行号的 `:source` 与 `:remaining-wait-ms`）。
   * 每次工具请求按参数 `:intent` 的 UTF-8 字节数 $\times 50\text{ms}$ 核定运行期限，到期同样自动转入 `:parked`（`:reason :deadline`）。
   * 在新命名程序中调用 `(unpark {:name "target" :value [812 842]})` 时，依次执行**观察核验（`:STALE_CONTROL`，单挂起点仅限恢复一次）**、**非自指核验（`:INVALID_ARGUMENT`）**、**存在性核验（`:PROGRAM_UNKNOWN`）**与**能力集核验（`:CAPABILITY_DENIED`）**，通过后按新请求 `:intent` 续期并将 `value` 原样作为原挂起表达式返回值继续执行直至提交。

## 5 消息投影、`Scope` 上下文管理、缓存对齐与 UFSS 规范

### 5.1 Wire Schema 协议门（`tool-gate`）与 `Scope` 出站裁剪

`src/tool-gate/index.mjs` 在 `before_provider_request` 为所有非豁免工具的 Wire Schema 注入必填字段 `must_think_in: "zh-cn"`、`:intent`（非空字符串，核定期限）与打平的 `:scope` 注解，并在 `tool_call` 执行前核验、记账与剥离：
* **四种 `:scope` 类型**：`:reset-scope`（必填 `:new-scope-goal` 与正整数 `:new-scope-retention-budget`；进程冷启后首个非豁免调用必须为此项，否则拒 `:SCOPE_UNINITIALIZED`）、`:keep-last`（扣 1 点 `retention`）、`:remove-last`（必填 `:replacement`，抹除上一拍弯路不扣预算）、`:me-too`（同回合多调用附议；全 `:me-too` 回合默认按 `:keep-last` 扣 1 点）。当 `retention === 0` 时非 `:reset-scope` 调用在准入前拒收 `:SCOPE_BUDGET_SPENT`。
* **投影不改写**：在 `context` 钩子中仅裁剪出站请求消息副本——最新已结算 `:reset-scope` 边界之后全留；边界之前仅保留人类操作员消息、历次 `:reset-scope` 调用与回执、`assume` 与 `askPreviousScope` 调用及回执、以及助手正文结论，绝不涂改宿主 `.jsonl` 会话文件。

### 5.2 Pair Hint 双块锚点保留与显式缓存断点前移

1. **双语纪律与未决续体提醒**：每次请求尾部注入 `AGENTS-LITE.md` 核心口诀、简体中文思考与输出硬约束、Token 经济校准，以及本会话当前处于 `:parked` 状态的程序名列表（Idle Hint）。
2. **看板观察（写者 clean-break / 读者 delta）与缓存对齐**：不设主动轮询看板的读取工具；他人修改看板时向尾部追加小 `delta`（上限 32 条 / 4 KiB，保持前序请求字节前缀严格不变）；个体自己写入看板或累积超阈值时执行个人视图 **clean-break**，用最新全量看板替换旧 `delta`。在 `before_provider_request` 中，自动将 Anthropic `cache_control` 或 Bedrock `cachePoint` 从末尾瞬态计数块前移至紧邻的最后一个稳定历史块。

### 5.3 EDN + UFSS 双向语法规范

* **系统输出一律 EDN + UFSS**：Pretty Printer 按确定性阶梯渲染字符串——含控制字符（`\r`、`\0` 等）回退标准转义 `"..."`；无 `"`、`\`、换行的单行输出 `"..."`；含 `"` 或 `\` 的单行取最小 $n \ge 1$ 输出 `#^n"..."#^n`（反斜杠零转义；正则统一写 `(re-pattern #"..."#)`）；多行文本取最小 $n \ge 0$ 输出独立缩进块 `#^n"""\n...\n<indent>"""#^n`。
* **模型输入自由归一化**：沙箱读取器原生解析 EDN + UFSS 与标准 Clojure 字符串（非空行缩进少于结束围栏 `<indent>` 时精确报错 `:UFSS_INDENT_VIOLATION`），外层工具参数兼容标准 JSON 与 EDN。

## 1 十条硬约束（不变量铁律）

以下十条是全系统的最高不变量。若后文细节与本节存在任何歧义，以本节为准：

1. **结构化与长文交付一律走专用工具调用。** 任何时刻需要大模型产出结构化数据（阶段元数据、CASE 清单、模块图、Slice 拓扑、评审台账、看板变更、审计打分、会诊建议）或大段文本（S1–S4 阶段文档、调查报告、审计报告），**必须通过带严格参数 Schema 的原生工具调用实现**（大段 Markdown/文本直接作为工具的大 `string` 参数传入，由框架校验并原子落盘）。严禁从大模型的自由聊天正文中用正则抠取业务数据或状态标记（如 `<approved/>`）。
2. **仅 S1 门禁征求人类同意，S2–S5 自动一气呵成。** 每个阶段均以调用专属门禁工具（`advance_s1` .. `advance_s4`）收尾并由框架保存文件、冻结 `sha256`。**唯有 `advance_s1` 实际停下弹窗征求人类操作员明确批准**（未批准则留在 S1 继续打磨）；一旦 S1 获批，`advance_s2`、`advance_s3`、`advance_s4` 校验通过后全部由框架自动保存文件并自动批准，无缝直入 S5 蜂群开发与并发实操验收，直至终局结案（常授权无人值守，Nudge 胜出）。（见 §2.2、§2.5）
3. **方法论按门禁回执渐进披露，严禁前置堆砌。** 基础系统提示词（`COMMON`）绝不提前暴露 S2–S5 的大师名字与阶段细则：S1 启动时只披露 S1 方法论；**S2 的大师与方法论仅在 `advance_s1` 获批的工具返回结果中首次披露**；**S3 仅在 `advance_s2` 的工具结果中披露**；**S4 仅在 `advance_s3` 的工具结果中披露**；**S5 仅在 `advance_s4` 的工具结果中披露**。`Scope` 投影引擎仅钉住当前所处阶段的门禁回执，阶段晋级后自动退役上一阶段的方法论长文，杜绝模型顾此失彼。（见 §2.2、§5.2）
4. **全 CASE 并发独立实操审计，框架确定性汇总。** S5 收尾验收时，若 `s2-manual-tests.md` 定义了 $K$ 个 `CASE-*`，框架**同时并发启动 $K$ 名独立的可见 `Manual Auditor` 子代理**（每名审计员仅负责 1 个 CASE，各自拥有独立的 `/tmp` 破坏实验目录、`tmux` 会话名与 `evidence/<case-id>/` 目录，对主工作区严格只读）。每名审计员通过 `submit_case_audit` 工具提交双视角得分与实操报告；框架负责收集全部 $K$ 份结构化结果、计算 `min(user_score, developer_score)`、汇总写出 `plans/<slug>/s5-report.md` 并裁决结案或打回返工。任何自动化测试、CI 或构建结果绝不构成验收证据。（见 §2.4）
5. **宏观中心化换任与微观去中心化蜂群严格咬合。** S5 每个 Slice 任期以中心化评估窗口（Phase A）开启：单一主模型 `Reviewer` 只读核验现场并调用 `submit_review`；若 `findings` 非空，`Reviewer` 退场、转化为看板根任务并唤醒 `@task` 蜂群（Phase B）并发施工；仅当看板全部根任务 `:done` 且无在途动作时，原子触发接力屏障（退休本任、建立上下文屏障、唤醒无前任对话包袱的新任 `Reviewer`）。（见 §2.4）
6. **父项始终保留实质，严禁子项完成自动关闭父项。** 看板中拆分优先于原子认领；父任务 `board_split` 出子项后进入 `:waiting`，子项全部 `:done` **仅解除父项等待使其恢复 `:ready`**，绝不自动折算为父项 `:done`，且严禁在同一回合顺手关闭刚恢复的父项。父项必须凭独立的合龙集成结果显式调用 `board_finish`。（见 §3.2）
7. **工作区写入一律经 ClojureScript 沙箱 VFS 干跑 + 纳秒 `stamp` + 写入口 $W$。** `cat`/`stat` 不加锁，自动采集精确凭据 `stamp = {:mtime-sec :mtime-nsec :size}`（忽略 `atime`）。`defprogram` 内的 `write`/`mkdir`/`rm`/`mv` 先按序作用于批内内存 VFS 视图；程序正常返回（或 `call` 前排空）时申请 worktree 写锁 $W$，锁内复核全部 `read-set`（含只读依赖文件）与结构条件，固定 `:applying` 资格后原子落盘。触盘前拒绝一切冲突，正常路径零回滚。（见 §4.2）
8. **抢令牌（`board_take_or_die`）不可逆，持令者独占 `call` 且无责即死，新生无记忆。** 普通个体在 `clj_worker` 中调用 `(call ...)` 一律拒收 `:TOKEN_REQUIRED`。个体仅在耗尽有价值的受保护工作且存在未结 `:needs-token` 任务时调用 `board_take_or_die`：赢者成为唯一 `Holder`，动态承担全看板 `:needs-token` 责任（仅在单次 `call` 运行期或文件提交期占 $W$）；输者在同一看板锁事务内公开移交剩余责任与认领并逻辑死亡；`Holder` 在 $R(a) = \emptyset$ 时同事务释放令牌并逻辑死亡。死亡槽位拉起全新 `agent_id`，绝不继承前世上下文。（见 §3.3）
9. **规划期源码只读锁与模型归属铁律。** S1–S4 的 `Plan` 代理除通过 `advance_s1..s4` 交由框架保存对应阶段文档外，无任何仓库文件写入能力；调查仓库事实只能调用同步工具 `devops`，复用本任期专属只读 `Plan DevOps`。`Plan`、`Reviewer`、`Manual Auditor` 与 `Blocker Oracle` 使用主模型（Main Model）；`Plan DevOps`、蜂群 `Worker` 与 `Holder` 一律使用 `@task` 模型；一切子代理在 Agent Hub 实名可见。（见 §2.1）
10. **投影不改写：出站 `Scope` 裁剪与系统输出一律 EDN + UFSS。** 每个非豁免工具调用必带 `:scope`、`:intent` 与中文思考锚点，`tool_call` 核验后剥离；历史裁剪仅作用于 `context` 出站副本，绝不改写宿主 `.jsonl` 历史。框架向大模型返回的一切工具回执、看板增量/快照、挂起诊断与错误详情一律渲染为 **EDN + UFSS（`#"..."#` 与 `#"""..."""#`）**。（见 §5.2、§5.3）

### 2.3 S5 多 Worktree Slice 编排与任期双相循环

1. **Slice 隔离与 FIFO `join` 队列**：
   * S5 调度器按 `s4-coordination.md` 为所有就绪 Slice 在 `.herd-worktrees/<slug>/<slice_id>` 创建独立 Git worktree；
   * 每个 Slice 内独立运行「Phase A 中心化 `Reviewer`（调 `submit_review`）⇄ Phase B `@task` 蜂群（围绕看板施工）⇄ 看板归零原子接力屏障」；
   * 继任 `Reviewer` 调用 `submit_review({ summary_markdown, findings: [] })` 独立确认合格且满足单任期 Quiescence 后，该 Slice 进入完成 FIFO 队列，在**主分支集成锁**下执行 `git rebase <base>` + `git merge --ff-only`（不可解淘汰冲突由 Slice `Holder` 调 `abandon_slice` 退出），解锁下游 Slice。

### 2.4 S5 全 CASE 并发独立实操审计与自动返工闭环

当所有 Slice 合入主工作区后，框架自动进入 S5 终局实操审计：

1. **前后双重复核**：启动前与全部审计子代理返回后，框架两次复核 `plans/<slug>/s1..s4-*.md` 的 `sha256` 与冻结契约一致；任何篡改直接阻断结案。
2. **$K$ 路审计员全并发启动**：
   * 设 `s2-manual-tests.md` 共解析出 $K$ 个用例 $\text{CASE}_1 \dots \text{CASE}_K$，框架通过 `Promise.all` **同时启动 $K$ 个 `runSubprocess` 可见子代理**（Agent Hub 实名显示为 `Auditor-CASE-01` .. `Auditor-CASE-K`，均使用主模型，单代理硬超时 30 分钟，绑定使命级递归 `AbortSignal`）。
   * **并发零踩踏物理隔离**：
     * 启动前框架采集主工作区文件 `stamp` 快照；所有 `Manual Auditor` 对主工作区产品与测试源码严格只读（审计结束后若主工作区产品文件被篡改，整批审计作废报错）；
     * 第 $i$ 名审计员拥有专属证据目录 `plans/<slug>/evidence/<case_id>/`、专属 `tmux` 会话命名空间 `herd-<slug>-<case_id>` 与专属临时破坏目录 `/tmp/herd-audit-<slug>-<case_id>-<uuid>/`，彼此完全正交。
   * 每名审计员仅接收 `s1` 背景与自己负责的那 1 个 `CASE-*`（含阈值、路径类别与 0–100 评分细则），亲自完成实操、抓屏与破坏验证后，必须调用结构化工具：
     `submit_case_audit({ case_id, user_score, developer_score, report_markdown, evidence_paths })`。
3. **框架确定性汇总与防绕过结案**：
   * 框架收集全部 $K$ 个工具回执，拒绝任何缺失、重复、未知 `case_id` 或越界非有限分数，逐项计算 `final_score = Math.min(user_score, developer_score)` 并对比 `threshold`；
   * 框架将 $K$ 份单 CASE 报告按文档顺序合成为总报告，原子写入 `plans/<slug>/s5-report.md`（含汇总得分表、各 CASE 实操证据与总判定 `PASS` / `FAIL`）；
   * **全 PASS**：框架签发绑定 `(missionId, revision)` 的结案凭证，使命置为 `:completed`（已交付）；
   * **任一 FAIL（或任一审计员异常中断）**：使命绝不停止，框架自动把所有未达标 CASE 及其审计员指出的具体缺陷转化为新一轮修复 Slice / 看板根任务，自动打回蜂群修复，修完再次并发跑审计，一气呵成直至全 PASS。

### 2.5 常授权无人值守与防停机 Nudge（含空转退避）

## 3 微观蜂群执行层：文件锁看板、拆分优先与 `take_or_die`

每个活动 worktree 的看板状态保存在 `.herd/missions/<slug>/slices/<slice_id>/board.edn`（配 `events.jsonl` 与字节偏移检查点），由排他文件锁 `.herd/locks/<slice_id>.board.lock`（`wx` 创建 + PID 存活探测 + 30s 陈旧锁回收）串行化短事务。

### 3.1 看板记录与责任集合 $R(a)$

维护 `Task`（`:state` 仅取 `"ready" | "waiting" | "done"`）、`Action`、`Actor`（`:slot-id` 复用，`:agent-id` 永不复用）与每 worktree 唯一的 `TokenSlot`。
个体 $a$ 的完整责任集合 $R(a)$ 为：未结非令牌自有任务 $\cup$（若 $a$ 为 `holder` 则含全看板所有未结 `needs_token` 任务）$\cup$ 处于 `applying | running | uncertain` 的活动动作。`"waiting"` 父项与运行中 `call` 均计入 $R(a)$。

### 3.2 结构化看板工具集与父项实质铁律

蜂群个体一律通过以下原生结构化工具操作看板：
1. **`board_split({ parent_id, expected_board_version, children, remaining_work, wait_for })`**：拆分优先于认领；创建子项、建立 `wait_for`、强制填写非空的父项合龙工作 `remaining_work` 并将父项置为 `"waiting"`。
2. **`board_claim({ task_id, atomicity_reason })`**：核验任务已原子化、`"ready"`、无冲突认领且令牌资格匹配，签发唯一 `claim_id`。
3. **`board_finish({ task_id, claim_id, result_markdown, dependency_paths })`**：
   * 若存在文件事实依赖，先取写锁 `$W$` 复核 `read-set` 与 `dependency_paths` 的纳秒 `stamp`；
   * 子项置为 `"done"` 后，若某父项的 `wait_for` 已全部 `"done"`，**仅将父项从 `"waiting"` 切换回 `"ready"`，绝不自动置为 `"done"`**，且硬性拒绝在同一回合内连带关闭刚恢复的父项；
   * 事务末尾重算 $R(\text{holder})$ 与根任务集，原子触发持令者无责退休或 Slice 任期接力屏障。
4. **维护与休眠工具**：`board_cancel`（仅叶子）、`board_replace`（仅叶子）、`board_release`、`board_reopen`、`board_comment`、`board_update`、`board_park_slot`（全局存在任何非阻塞可推进工作时严禁休眠）与 Holder 专属的 `abandon_slice`。

### 3.3 `board_take_or_die` 与只读 `Blocker Oracle`

* **`board_take_or_die({ request_id, confirm, handoff_markdown })`**：`confirm` 必须精确为 `"i-hereby-confirm-i-die-without-regret"`。赢则升为唯一 `Holder` 并签发新 `term_id`；输则同事务解除认领、清空普通责任（含 `"waiting"` 父项）的 `owner_id` 归还公共池、标 `dead`，销毁当前子会话并在原槽位拉起全新无记忆 `agent_id`。完整满足 **T01–T13** 与 **V01–V08**。
* **只读 `Blocker Oracle`**：同一阻塞指纹连续失败达阈值时自动拉起主模型只读子会话，调用 `submit_oracle_advice` 将替代方案写入看板评论。

## 4 ClojureScript 沙箱（`clj_*`）、批内 VFS 干跑与续体恢复

### 4.1 隔离求值器与单一语法纪律

工作区文件探查、精确切片编辑与受管命令执行统一通过角色沙箱工具（`clj_plan`、`clj_devops`、`clj_review`、`clj_worker`、`clj_auditor`，参数 `{ program_name, code, intent }`）执行。
* **零 JVM 物理隔离**：基于 `cherry-cljs` 的不可变持久集合（Vector / Map / Set / List / Keyword / Symbol）与纯函数库（`cljs.core`、`clojure.string`、`clojure.set`、`clojure.walk`）构建异步求值器；符号表物理隔绝 `js/*`、`globalThis`、`process`、`Bun`、`require`、`import`。
* **裸函数 + 单 EDN Map 参数**：沙箱内能力一律采用 `(cat {:path ...})`、`(stat {:path ...})`、`(ls {:path ...})`、`(write {:path ... :content ...})`、`(mkdir {:path ...})`、`(rm {:path ...})`、`(mv {:source ... :target ...})`、`(where {:content ... :needle ...})`、`(whereAll {:content ... :needle ...})`、`(park {:payload ...})`、`(unpark {:name ... :value ...})`、`(call {:command ...})`。

### 4.2 批内内存 VFS 干跑视图与写锁 $W$ 提交

1. **无锁纳秒 `stamp` 采集**：`cat`/`stat` 读底层文件时用 `fs.lstatSync(path, { bigint: true })` 记录 `{:mtime-sec :mtime-nsec :size}`（忽略 `atime`；前后不一致报 `:changed-during-read`）；`ls` 仅作纯探查，不进 `read-set`。
2. **批内顺序干跑**：`write`/`mkdir`/`rm`/`mv` 仅修改本次程序私有的内存 VFS 叠加层（后一步操作立即看到前一步移动或写入的结果；单文件上限 2 MiB，单批 16 MiB / 256 操作）；异常或挂起时**真实磁盘零修改**。
3. **锁内复核与原子落盘**：`defprogram` 正常返回（或 `call` 前排空）时获取 worktree 写锁 `$W$`（`.herd/locks/<slice-id>.write-w.lock`），复核 `read-set` 全部文件（含只读依赖）的 `stamp` 与结构条件；冲突立即释放 `$W$` 返回 `:FILE_CONFLICT`；通过则登记 `:applying`，以同目录 `.tmp` + `fsync` + `rename` 原子落盘后释放 `$W$`。`Holder` 的 `call` 仅在单次命令运行期占 `$W$`，等待期释放 `$W$`。完整满足 **F01–F15**。

### 4.3 `where` 带状 DP 诊断与 `park` / `unpark` 续体恢复

* `(where {:content src :needle needle})` 命中数不为 1 时自动触发 Promise 续体挂起：多匹配返回最多 8 条 `±80` 码元上下文候选；零匹配采用 Ukkonen 带状 DP（$K=64$，前 2000 非空行，10M 单元预算）返回最小编辑距离行 `:nearest`。
* 挂起时全部词法局部变量与未提交的批内 VFS 视图悬停在本 `agent_id` 内存 `ParkedPrograms` 表中，外层工具立即返回 EDN + UFSS 挂起回执（含带行号的 `:source`）；后续程序经四道防呆核验调用 `(unpark {:name ... :value [b e]})` 即可将 `[b e]` 注入原挂起表达式继续跑完提交。
