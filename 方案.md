# 方案：用猴子补丁让扩展调用宿主官方 read/write

## 目标

沙箱 `clj_devops` 的 `(read ...)` / `(write ...)` 必须调用宿主官方 read/write，禁止 fs 绕过，禁止退化。当前宿主扩展 API 不暴露 Runner，因此用受控猴子补丁捕获 `ExtensionRunner` 实例，再调用其公开方法 `invokeNativeTool`。

## 已证实的事实

- `../oh-my-pi/packages/coding-agent/src/extensibility/extensions/runner.ts:518` 导出 `ExtensionRunner`。
- `runner.ts:674-679` 的 `setNativeToolResolver` 由宿主注入 native 工具解析器。
- `runner.ts:724-754` 的 `invokeNativeTool(name, params, { signal, onUpdate, depth, callerContext })` 直接执行 native built-in。
- `runner.ts:1583-1680` 的 `createContext(model, delegation, agent)` 只在 `delegation.toolName` 存在时注入 `ctx.invokeTool`，内部转调 `invokeNativeTool`。
- `../oh-my-pi/packages/coding-agent/src/extensibility/extensions/wrapper.ts:132` 的 `ExtensionToolWrapper.execute` 是唯一注入 `createContext(undefined, { toolName })` 的地方，且只交给该工具自己的 execute。
- `types.d.ts:1348` 的 `ExtensionAPI` 与 `types.d.ts:537` 的 `ExtensionContext` 都没有 `runner` / `invokeNativeTool`。

## 补丁点

在 `src/host/imports.mjs` 深导入宿主内部模块，patch `ExtensionRunner.prototype.createContext`，在首次调用时保存 `this`：

```js
import { ExtensionRunner } from '@oh-my-pi/pi-coding-agent/dist/extensibility/extensions/runner.js';

let capturedRunner = null;
let restore = null;

export function installRunnerCapture() {
	if (restore !== null) return restore;
	const original = ExtensionRunner.prototype.createContext;
	ExtensionRunner.prototype.createContext = function patchedCreateContext(...args) {
		capturedRunner = this;
		return original.apply(this, args);
	};
	restore = () => {
		ExtensionRunner.prototype.createContext = original;
		restore = null;
	};
	return restore;
}

export function getNativeRunner() {
	return capturedRunner;
}
```

补丁在扩展模块加载时执行一次；`createContext` 的调用由宿主在事件分发与工具包装时触发，因此不需要主动构造 Runner。

## 调用路径

`src/clj-main.mjs` 的 `invokeHostTool` 改为：

```js
const invokeHostTool = async (ctx, name, params) => {
	const runner = getNativeRunner();
	if (!runner || typeof runner.invokeNativeTool !== 'function') {
		throw herdError('HOST_API_MISMATCH', `native ${name} delegation is unavailable`, { tool: name });
	}
	if (name !== 'write') {
		return await runner.invokeNativeTool(name, params, {});
	}
	const lockDir = join(rootFor(ctx), '.herd', 'locks');
	mkdirSync(lockDir, { recursive: true });
	const acquired = await withLock(join(lockDir, 'clj-core.cross-process.lock'), { lock_id: 'clj-core' }, async () => {
		if (params.__expectedStamp !== undefined) {
			const absolute = resolve(ctx.cwd ?? process.cwd(), params.path);
			const stats = lstatSync(absolute, { bigint: true });
			const expected = params.__expectedStamp;
			const actual = stats === null ? null : {
				mtimeSec: Number(stats.mtimeNs / 1000000000n),
				mtimeNsec: Number(stats.mtimeNs % 1000000000n),
				size: Number(stats.size),
			};
			if (actual === null || actual.mtimeSec !== expected.mtimeSec || actual.mtimeNsec !== expected.mtimeNsec || actual.size !== expected.size) {
				throw herdError(':FILE_CONFLICT', `file changed since read: ${params.path}`, { path: params.path });
			}
			delete params.__expectedStamp;
		}
		return await runner.invokeNativeTool('write', params, {});
	});
	if (acquired?.ok) return acquired.value;
	throw herdError(acquired?.code ?? ':BOARD_CONFLICT', acquired?.message ?? 'cross-process write lock is held');
};
```

`detectHostTools` 改为：

```js
const detectHostTools = () => {
	const runner = getNativeRunner();
	return {
		read: runner !== null && runner.hasNativeTool('read'),
		write: runner !== null && runner.hasNativeTool('write'),
	};
};
```

删除：`hostShadowTools` 注册（read/write shadow 工具）、`hostToolOf`、`invokeHostTool` 里对 shadow 的分支。`applyCljToolSurface` 的 blacklist 不再误伤自定义同名工具（因为不再注册同名工具）。

## 风险与合规

- 违反 `AGENTS.md` §1.1 与 §9.6 的“禁止猴补丁”；本方案是用户明确要求的例外，必须写入 `HACK.md`，并在 `AGENTS.md` 由人类操作员批准后修订例外条款。
- 深路径导入 `dist/extensibility/extensions/runner.js` 依赖宿主内部布局；必须集中在 `src/host/imports.mjs`，版本漂移时只改一处。
- `invokeNativeTool` 依赖 `#nativeToolResolver`；若宿主未注入，会抛 `invokeTool: no native built-in named ...`，此时 fail-closed，不退回 fs。
- 省略 `callerContext` 会让原生 write 使用 `resolved.makeContext()`；若需要保留 toolCall 元数据（LSP 批量刷新），可传宿主工具执行 ctx，但扩展侧拿不到，先接受该限制并记录。
- 补丁必须在宿主第一次 `createContext` 之前安装；若扩展加载晚于首次调用，捕获可能为空，需要在 `before_agent_start`/`session_start` 时重试或 fail-closed。

## 验证

1. `node --check src/host/imports.mjs src/clj-main.mjs`。
2. `bun test tests/sandbox-tools.test.mjs tests/clj-core.test.mjs`（回归 70 pass）。
3. 真实 `clj_devops` 执行 `(read {:path "package.json"})` 与 `(write {:path ".herd/tmp-probe" :content "ok"})`，确认回执来自宿主工具、无 HOST_API_MISMATCH。
4. 删除探针文件，检查 `.herd/locks/clj-core.cross-process.lock` 已释放。

## 回滚

移除 `installRunnerCapture` 调用与 `invokeHostTool` 的 runner 分支，恢复 fail-closed；不得以 fs 作为回滚路径。
